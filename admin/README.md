# Mobius 관리 콘솔

Mobius 와 **같은 저장소, 다른 프로세스**로 도는 관리자용 서버.

만료·고아 리소스를 조회하고, 골라서 삭제하거나 `et` 를 연장한다.

## 무엇을 보여 주는가

### 만료된 리소스

`et`(expirationTime)가 이미 지난 것들. 배포 서버 표본에서 `et` 값의 약 81% 가
이미 과거였다. 만료 스윕은 **주기 실행이 걸려 있지 않아서**(자동으로 돌리면
지금까지 안 지워진 것이 한꺼번에 사라진다) 이 목록은 저절로 줄어들지 않는다.

목록은 타입별로 다르게 표시한다. 판단에 필요한 구분이기 때문이다.

| 표시 | 뜻 |
|---|---|
| 자동 삭제 안 됨 | AE·CNT·CSEBase. 삭제 경로가 의도적으로 제외한다 — 계속 쌓이는 쪽이 이들이다 |
| 만료 시 자동 삭제 | ACP. 사라지면 참조하던 리소스의 유효 권한이 조용히 바뀐다 |
| 수동 정리 대상 | 그 외 |

### 고아 리소스

부모(`pi`)가 `lookup` 에 없는 행. 트리에서 도달할 수 없지만 DB 에는 남는다.

고아는 이 서버의 **정상 실패 모드**다. `DELETE` 는 루트 행만 지우고 `200` 을
돌려준 뒤 자손을 배경에서 지우므로(`delete_descendants_background`), 그 도중
프로세스가 죽거나 커넥션을 못 빌리거나 대형 서브트리가 타임아웃에 걸리면 남은
자손이 통째로 고아가 된다.

**화면의 숫자는 "끊긴 지점"의 개수이지 도달 불가 데이터의 총량이 아니다.**
고아 판정은 *직계* 부모가 없는 행이라, 끊긴 지점 아래의 행들은 자기 부모가
있으므로 세지지 않는다 — 하지만 위가 끊겼으니 똑같이 도달할 수 없다. 끊긴
컨테이너 하나 아래에 CIN 수백만 건이 있을 수 있다. 정리가 여러 패스를 도는
이유이기도 하다.

### 권한 (ACP)

코어 계약은 `docs/superpowers/specs/2026-08-29-acp-console-contract.md` 에 있고,
콘솔은 그 함수들을 `require` 해서 직접 부른다.

| 화면 | 무엇을 답하는가 |
|---|---|
| 문제 | 이미 저장된 잘못된 값. **여기부터 본다** |
| ACP 목록 / 상세 | 이 ACP 는 무엇을 허용하고, 누가 쓰고 있는가 |
| 시뮬레이터 | 이 리소스에 누가 무엇을 할 수 있는가 |

배포 실측(2026-08-29)에서 ACP 리소스는 1개, `acpi` 가 채워진 리소스는 2개였고
그중 하나가 없는 ACP 를 가리켜 수퍼유저 말고는 아무도 못 쓰는 상태였다. 화면의
목적은 권한을 예쁘게 보여 주는 것이 아니라 **잘못 걸린 것을 찾아내고, 걸기 전에
결과를 미리 보는 것**이다.

화면이 반드시 말하는 것 넷:

- **생성자는 ACP 와 무관하게 통과한다.** 어떤 ACP 를 걸어도 `cr` 은 남으므로
  "완전히 잠갔다" 는 표시를 하지 않는다. 시뮬레이터가 `decided_by: 'creator'`
  로 통과한 칸을 다른 색으로 칠하고, 몇 칸이 그런지 세어 보여 준다.
- **확인하지 못한 것을 0건으로 보여 주지 않는다.** 특히 `grp.macp` 참조 —
  fanOutPoint 는 `acpi` 가 아니라 `macp` 로 판정하므로, 스캔이 실패했는데
  "0건" 이라고 하면 ACP 를 지워도 된다는 거짓 신호가 된다.
- **컨테이너 `acpi` 는 조상과 합쳐지지 않고 덮어쓴다.** 가장 가까운 것 하나만
  쓰이므로, 중간 컨테이너에 `acpi` 가 생기면 AE 의 ACP 를 고쳐도 먹지 않는다.
  시뮬레이터가 `source: 'inherited'` 일 때 그 사실을 띄운다.
- **관찰 모드는 거부를 허용으로 내보낸다.** `acpObserveMode: 'observe'` 면 화면
  맨 위에 항상 경고가 뜬다. 다만 이것은 **콘솔이 읽은 `conf.json` 이지 워커의
  실제 상태가 아니다** — 워커는 자기 프로세스 메모리에 들고 있고 콘솔은 거기
  닿을 수 없다. 화면도 그렇게 밝힌다.

**콘솔은 자기 자신을 검증받지 않는다.** `adminOrigin` 이 `superUser` 라
`security.js` 가 무조건 통과시키므로, HTTP 로 왕복해도 정책을 원리적으로 검증할
수 없다. 그래서 시뮬레이터가 필요하다 — `security.js` 의 평가 함수를 그대로 쓴다.

> **알려진 제약:** 시뮬레이터의 "`acpi` 를 뗐다고 가정하고 보기" 는 잠가 두었다.
> 코어의 `acp_simulate.js` 가 빈 `acpiOverride` 를 상속·기본정책 경로가 아니라
> ACP 조회 경로로 보내, 실제와 **반대로** 답한다(실측: 실제로는 전원 허용인데
> 전원 거부라고 답한다). 코어가 고쳐지면 잠금만 걷으면 된다.

## 무엇을 할 수 있는가

선택한 리소스에 대해 일괄 작업을 건다. 대상이 수천 건이면 요청-응답 안에서
끝나지 않으므로, 작업을 만들어 id 를 돌려주고 화면이 진행률을 폴링한다.

| 작업 | 비고 |
|---|---|
| 만료 리소스 삭제 | 삭제 직전 `et` 를 다시 확인한다 |
| `et` 연장 | CIN 은 oneM2M 상 UPDATE 자체가 `405` 라 건너뛴다 |
| 고아 리소스 삭제 | 삭제 직전 부모가 여전히 없는지 다시 확인한다 |

**한 번에 한 작업만 돈다.** 두 작업이 같은 서브트리를 건드리면 서로의 `404` 를
실패로 세게 되고, 무엇보다 관리자가 "지금 무엇이 지워지는 중인가" 를 하나로 볼
수 있어야 한다. 두 번째 요청은 `409` 와 함께 도는 작업을 돌려준다.

**프리플라이트가 낡은 목록으로부터 지킨다.** 목록은 몇 분 전 것일 수 있다. 그
사이 누가 `et` 를 늘렸거나 부모가 되살아났는데 낡은 목록을 믿고 지우면 되돌릴
수 없다. 한 건당 조회 한 번이 늘지만, 삭제는 되돌릴 수 없으므로 그 값을 치른다.
건너뛴 건은 이유와 함께 화면에 남는다.

## 실행

`conf.json`(Mobius 와 같은 파일)에 아래를 넣는다.

```json
{
  "adminPassword": "...",
  "adminPort": 7580,
  "adminHost": "127.0.0.1",
  "adminCseHost": "127.0.0.1",
  "adminCsePort": 7579,
  "adminOrigin": "Sponde"
}
```

| 키 | 기본값 | 뜻 |
|---|---|---|
| `adminPassword` | (없으면 뜨지 않음) | 콘솔 로그인 비밀번호 |
| `adminPort` | `7580` | 콘솔 포트 |
| `adminHost` | `127.0.0.1` | 바인드 주소 |
| `adminCseHost` | `127.0.0.1` | 쓰기를 보낼 Mobius 주소 |
| `adminCsePort` | `csebaseport` | 쓰기를 보낼 Mobius 포트 |
| `adminOrigin` | `superUser` | 콘솔이 쓰는 `X-M2M-Origin` |

`adminPassword` 가 없으면 뜨지 않는다. "일단 열어 두고 나중에 잠근다" 가 되면
나중은 오지 않는다.

`adminHost` 는 기본이 루프백이다. 조회만 해도 운영 리소스 트리를 그대로 보여
주므로 기본값이 외부 공개면 안 된다.

`adminCsePort` 를 못 찾으면 **조회 전용으로 뜬다.** 주소를 추측해서 다른 곳에
`DELETE` 를 쏘는 일은 없어야 한다.

> **`adminOrigin` 의 기본값은 `superUser` 다.** 관리 콘솔은 어떤 리소스든 지울
> 수 있어야 하는데 그러려면 ACP 를 통과해야 하고, `security.js` 가 이 값에 대해
> 무조건 통과시킨다. **즉 콘솔 비밀번호는 사실상 superUser 키와 같은 힘을
> 가진다.** ACP 로 제한하고 싶으면 `adminOrigin` 에 별도 AE-ID 를 넣는다 —
> 그러면 콘솔은 그 AE 가 권한을 가진 리소스만 지울 수 있다. 화면 오른쪽 위
> 배지가 지금 어느 쪽인지 보여 준다.

```
# 프런트엔드 빌드 (한 번)
cd admin/web && npm install && npm run build

# 콘솔 실행 (백엔드는 Mobius 와 같은 규칙 — argv 가 conf 를 이긴다)
node admin/server.js sqlite
node admin/server.js mysql
```

개발 중에는 Vite dev server 를 쓴다. `/api` 는 콘솔 서버(7580)로 프록시된다.

```
cd admin/web && npm run dev     # http://localhost:5173
```

## 설계 메모

**읽기는 DB 를 직접 본다.** oneM2M discovery 로는 "만료된 리소스를 `et` 순으로"
같은 질의를 표현할 수 없다. `mobius/db` 파사드를 그대로 쓰므로 MySQL/SQLite 를
콘솔이 따로 알 필요가 없다.

**쓰기는 oneM2M HTTP API 를 지난다**(`admin/cse.js`). 인수인계 문서는 만료 삭제에
`delete_lookup_et`(DB 직접)를 권했지만, 콘솔은 별도 프로세스라 워커들의 캐시
무효화 IPC 에 낄 수 없다 — DB 를 직접 지우면 워커들이 지워진 리소스를 계속
`200` 으로 돌려준다. 구독 알림, 부모 카운터 되돌리기, 하위 트리 삭제도 전부 앱
레이어에 있다. 대가는 요청 N회지만 배치 크기는 관리자가 정한다.

**전체 건수를 세지 않는다.** 배포의 `lookup` 은 5,740만 행이고 MySQL 에는 `et`
인덱스가 없다. 끝까지 세면 풀스캔이라, 상한에서 끊고 "47+" 처럼 보여 준다.

**페이징은 키셋이다.** 만료 목록은 `(et, ri)`, 고아 목록은 `ri`. 오프셋 페이징은
뒤로 갈수록 느려진다. `et` 하나만으로는 같은 `et` 를 가진 행이 잘려 유실되므로
`ri` 를 함께 쓴다.

**고아 조회에 조인을 쓰지 않는다.** 배포 스키마는 `lookup.pi` 가
`utf8mb3_general_ci`, `lookup.ri` 가 `utf8mb3_bin` 이라 부모↔자식 조인이 인덱스를
타지 못한다(측정: 컨테이너 50개에 LEFT JOIN 이 20초 초과). 키셋으로 전진하며
배치마다 리터럴 `whereIn` 으로 부모 존재를 확인한다.

**목록은 작업이 끝난 뒤에 다시 읽는다.** 작업 생성 응답(`202`)은 시작을 뜻할
뿐이라, 그때 읽으면 삭제가 도는 중의 상태를 찍는다. 그래도 Mobius 의 배경
캐스케이드는 응답 뒤에도 이어지므로, 갓 끝난 직후의 목록은 아직 움직이는 중일
수 있다.

**작업 상태는 메모리에만 둔다.** 콘솔은 클러스터를 쓰지 않으므로 프로세스 하나가
전부를 안다. 재시작하면 진행 중이던 작업 기록은 사라지지만 이미 삭제된 것이
되살아나지는 않는다 — 어디까지 지웠는지는 목록을 다시 조회하면 그 자체로 드러난다.
