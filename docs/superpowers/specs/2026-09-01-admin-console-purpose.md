# 관리 콘솔 목표 재정의

- 작성일: 2026-09-01
- 계기: 사용자 지시 — *"단순하게 리소스 관리나 권한을 UI로 관리하면 좋겠다는
  생각이었는데, 하다 보니까 전체 모비우스 서버 설정, db 설정, 실행과 종료의
  기능이 추가되면서 기능이 확대가 되었어. 다시 한번 정리해서 목표를 명확히
  하면 좋겠어."*
- 원 설계: `docs/superpowers/specs/2026-08-28-admin-console-design.md`
  (커밋 `1e6a1e5`)

---

## 0. 결론 — 문제는 "확대" 가 아니다

사용자가 느낀 것은 **기능이 늘었다**는 것인데, 대조해 보니 실상은 다르다.

> **원래 목표 넷 중 온전히 이행된 것은 하나뿐이다. 그런데 설계에 없던 층 둘은
> 완성되어 있다.**

즉 이것은 "할 일을 다 하고 더 나갔다" 가 아니라 **"본체를 절반쯤 지어 둔 채
옆 건물을 올렸다"** 에 가깝다. 목표를 다시 세우는 일의 절반은 뺄 것을 정하는
것이고, 나머지 절반은 **안 지어진 본체를 되찾는 것**이다.

---

## 1. 원래 무엇이었나

목적 문장(설계 27줄):

> 이 콘솔은 그 구멍을 사람이 메우는 도구다. 자동 삭제 범위를 넓히는 대신
> **관리자가 확인하고 판단해 삭제하거나 만료를 연장하는 경로**를 제공한다.

인수인계 문서가 한 겹 더 좁힌다(`2026-08-29-admin-ui-handoff.md:16`):

> 두 경우 모두 **자동으로 돌리면 되돌릴 수 없는 삭제나 대량 변경이 일어난다.**
> 그래서 코드는 "판정하고 목록을 돌려주는 것" 까지만 하고 멈춘다.

**목표 넷**(29–34줄)과 **비목표 다섯**(36–42줄)이 명시돼 있다. 비목표 첫 줄이
성격을 정한다 — *"Mobius 의 자동 만료 삭제 범위 확대(위험하고, 이 콘솔이 그
역할을 대신한다)."*

### 이 문서가 작업 브랜치에 없었다

`2026-08-28-admin-console-design.md` 는 **이 워크트리에 없다.** 원 저장소와
이력(`1e6a1e5`)에만 있다. 그 결과 감시 문서(`2026-08-30-admin-console-backlog.md`)
가 **목표/비목표 목록을 한 번도 대조하지 않았다.** 범위가 흐려진 구조적 조건
중 하나다.

## 2. 원래 목표의 현재 이행 상태

**여기가 이 문서의 핵심이다.** 전부 코드로 확인했다.

| 원래 목표 | 상태 | 근거 |
|---|---|---|
| ① 리소스 트리와 생성·수정·만료 시각, **최근 사용 여부** 확인 | **화면이 없다** | `views/` 에 리소스 조회·검색 화면 없음. `hit_ri` 는 `admin/` 어디에도 없음(선행 P0-2 미착수) |
| ② 만료·**임박** 리소스를 걸러 삭제하거나 연장 | **절반** | ExpiredView 동작. 그러나 "임박" 은 없다 — `/api/expired` 는 이미 만료된 것만 |
| ③ ACP 확인·편집·**리소스에 연결/해제** | **절반** | 화면 4개 동작. `acpi` 연결/해제 없음. ACP 생성 없음(비목표의 유일한 예외였다) |
| ④ 별도 프로세스·별도 포트 | **완료** | `admin/server.js` 독립 기동 |

대조군 — **설계에 없던 층 둘은 닫혀 있다.**

| 설계에 없던 것 | 상태 |
|---|---|
| conf.json 편집 | ConfView + `conf_store.js` 228행. 원자적 쓰기·관문 두 겹·비밀 마스킹까지 완결 |
| 기동·정지·재기동 | ServerControl + `process_ctl.js` 242행. pm2 분기·pid 소유 확인·유예 폴링까지 완결 |

### 명시적 비목표를 위반한 것 하나

설계 341줄:

> 고아 탐지 · `LEFT JOIN lookup p ON l.pi=p.ri WHERE p.ri IS NULL` ·
> **배치 전용. 화면에서 라이브 실행 금지**

`OrphanView` 는 화면에서 "더 찾기"·"다시 세기" 로 라이브 스캔한다. 금지된 것을
하고 있다. (배포 `lookup` 은 5,740만 행이다.)

### 설계가 필수라고 적은 안전장치가 없다

설계의 일괄 작업 6단계 중 구현은 셋이다. 없는 것:

- **삭제 전 JSON 아카이브** (설계가 필수로 표시)
- **감사 로그** — `admin/audit.js` 없음
- **카나리 10건**, 삭제 사후 검증, 제3의 결론 '보존'
- **`admin.db` 영속 계층 전체.** 세션도(`server.js:117`) 작업 상태도
  (`jobs.js:8`) 메모리다. 콘솔을 재시작하면 도는 작업과 흔적이 사라진다

**되돌릴 수 없음에 대비하려던 장치가 없는 상태에서, 되돌릴 수 없음의 폭이 더
큰 층이 먼저 들어왔다.**

## 3. 어떻게 커졌나 — 출처별

`admin/` 과 스펙을 건드린 커밋 38건의 분포다.

| 출처 | 건수 | 그중 기능 범위를 넓힌 것 |
|---|---|---|
| 원래 목적 | 7 | 7 |
| 다른 세션 경유 | 15 | 2 (고아 화면, 구독 화면 설계) |
| 사용자 추가 요청 | 8 | **5** (conf 쓰기 계층, 설정 화면 3, 프로세스 제어) |
| 스스로 판단 | 8 | 0 |

### 확대는 사용자 지시로 들어왔다 — 다만 연쇄였다

    58bacce   "conf.json 설정값을 설정할 수 있게, 필요한 것만 노출해서"
    3d36767   "body limit 설정을 관리 UI 에서"
    32d6558   "파라미터들을 카테고리로 분류"
    1f20241   기동·정지·재기동

마지막 커밋이 스스로 적은 동기: *"설정 화면의 가장 큰 약점이 '저장해도 아무
일이 안 일어난다' 였는데, 재기동이 붙어 저장→재기동 한 흐름으로 닫힌다."*

**프로세스 제어는 사용자가 지시했지만, 그 지시를 부른 결함은 직전 확대가 만든
것이다.** 설정 편집은 원리적으로 "적용됐는지" 를 모른다(`runtimeKnown` 항상
false — `cluster.fork` 가 엔트리를 재실행해 워커마다 값이 다를 수 있다). 그
공백이 재기동 버튼을 요구했다.

### 그 다음 고리는 내가 만들었다

기동·정지와 함께 **`guard_busy`(도는 작업이 있으면 정지 409)** 를 붙였다. 이건
사용자 지시가 아니라 내 판단이다. 그리고 그것이 두 층을 서로 잠갔다 —
`cse.js` 가 끊긴 응답에 콜백을 부르지 않으면 작업이 갇히고, `guard_busy` 가
서버 제어를 **영구히** 막았다(`ed776f6`, `d0ff60d` 로 45초 유예를 넣어 해소).

> 정정 — 이건 운영 사고가 아니라 **내가 직접 시험하다 찾은 것**이다. 배포에서
> 일어난 적은 없다.

### 요청 없이 내가 넣은 것

범위를 넓힌 것은 없지만, 지시·요청 근거가 커밋에 없는 것이 있다.

- `8faac46` 오션 테마 전면 재도색과 가독성 조정
- `c031de6` ACP 정책 안내문(`AcpPolicyNote`)
- `eaf440b` 에이전트 73개로 전 브랜치를 훑은 추적 문서

나머지(응답 본문 상한, 취소 유예, 상수 드리프트 발견 등)는 견고성·자기검증이고
화면을 늘리지 않았다.

### 승인 단계가 없는 유입 경로가 하나 있다

코어 세션이 자동 실행을 뺄 때마다 커밋에 **"관리자 UI 로 넘긴다"** 고 적고,
그 목적지가 여기다. 고아 화면이 그렇게 들어왔다 — *"lite 가 고아 정리의 자동
실행을 빼고 '관리자 UI 로 넘긴다' 고 했는데 그 UI 가 없었다."* 대형 컨테이너
카운터도, 구독 감사도 같은 경로로 대기 중이다.

설계 목표 넷에 고아 정리는 없다. 문서의 **정신**에는 맞지만 **아무도 이 항목을
승인한 적이 없다.**

### 사용자 결정이 범위를 줄인 것은 하나다

- `53b7e77` 알림 판정 DB 저장 철회 — **축소**
- `2affdbf` 만료 SUB 노출은 의도된 설계 — 빼려던 것을 안 뺀 것이므로 **유지**

## 4. 성격이 다른 것들이 한 덩어리가 된 지점

대상이 **데이터 / 규칙 / 프로세스** 로 갈리는데 셸·인증·세션이 하나다.

### (1) 자물쇠가 하나다

세 층 전부 conf.json 의 **공유 비밀번호 하나**로 열린다. 세션에는 `{created}`
뿐이라 감사 로그에 '누가' 를 적을 수 없다. **만료 리소스 한 건 삭제와 서비스
전체 정지가 같은 자물쇠다.**

콘솔은 이미 같은 논리를 알고 있다. MySQL 쓰기를 검토할 때 *"전용 DB 계정은
경계가 아니다 — 콘솔이 그 자격증명을 들고 있고 인증은 비밀번호 하나뿐"* 이라고
결론냈다(§2.8). **같은 논리가 프로세스 제어에도 그대로 적용되는데, 거기서는
답이 달랐다.**

### (2) 확인 절차가 위험과 반대로 붙어 있다

| 동작 | 관문 |
|---|---|
| 리소스 삭제 | 프리플라이트 + 확인 대화상자(대상 표시) + 진행률·실패 사유 + 취소 — **네 겹** |
| 서버 정지·재기동 | 인라인 확인 한 번 + "도는 작업 없을 것" — **한 겹** |

가장 파괴력이 큰 동작이 가장 가벼운 관문을 지난다.

### (3) 되돌릴 수 있음의 단위

| | 단위 | 되돌리기 |
|---|---|---|
| 리소스 삭제 | 행 N건 | **불가** (아카이브로 대비하려 했으나 없음) |
| et 연장 / ACP 편집 | 행·ACP 1건 | 가능 |
| conf 저장 | 파일 | 가능. 단 다음 재기동에 워커 전부 적용 |
| **서버 정지** | **서비스 전체** | 재기동. **정지된 채 방치될 수 있는 유일한 동작** |

### (4) 확신할 수 있는 것은 줄어드는데 할 수 있는 일은 커진다

- **리소스 층** — 캐시 제거 이후 콘솔이 DB 에서 읽은 것 = 서버가 응답하는 것.
  화면이 참말을 할 수 있다.
- **설정 층** — "지금 적용 중인 값" 을 **원리적으로 모른다**.
- **프로세스 층** — 포트가 열렸는지, 우리가 띄운 pid 인지까지만.

이 역전이 문제의 핵심이다.

### (5) 코어 계약이 있는 층과 없는 층

리소스·ACP·설정은 코어 함수/스키마 위에 선다. 그래서 코어가 고치면 콘솔은 한
줄도 안 고치고 좋아진다 — `maxBodyBytes` 가 코어에 등록되자 화면에 저절로
나타났다. **프로세스 층에는 대응하는 코어 계약이 없다.** pm2 유무·pid 파일·포트
폴링은 콘솔이 혼자 정한 규약이고, 유지보수를 콘솔이 전부 떠안는다.

## 5. 목표 재정의안

> **관리 콘솔은 Mobius 가 자동으로 하지 않기로 한 판단을 사람이 내리는
> 자리다. 데이터(리소스·권한)에 대한 판단이 본체이고, 서버의 동작 규칙(설정)은
> 그 판단을 실행하는 데 필요한 만큼만 다루며, 서버와 DB 의 생사는 다루지
> 않는다.**

경계는 **규칙과 생사 사이**에 긋는다.

### 0층 — 말하는 방식 (전 층 공통)

읽기는 DB 직접 / 쓰기는 CSE 경유. 상한에 걸리면 `capped` 를 노출. 근거가 없으면
단언하지 않고 빈 칸. **코어 정책을 화면이 상수로 베끼지 않는다.**
`acpi like '%…%'` 와 전역 `COUNT(*)` 는 금지(5,740만 행).

**지금 위반 4건 이상** — 이게 재작업 첫 순번이다.

1. `AUTO_DELETED_RISKY` 가 ACP 에 없는 시한을 붙인다
2. `ET_EXTENDABLE` 이 코어가 연장해 주는 타입을 막는다 (서버에도 사본이 있어
   UI 우회해도 같다)
3. `AcpProblemsView` 가 `more/nextRi` 를 무시해 ACP 200개 넘으면 조용히 잘린다
4. `acpDiscoveryFilter` 미노출 — `'off'` 면 시뮬레이터가 **보호를 과장**한다

### 1층 — 판단 대기열 (본체)

코어가 "판정하고 목록만 돌려주고 멈춘" 것들. **먼저 되찾을 것은 목표 ①②다** —
리소스 조회 화면, `hit_ri` 사용 이력, **만료 임박**.

그 다음이 안전장치 복구(아카이브·감사·`admin.db`). **안전장치 없이 대기열을
늘리지 않는다.**

대기 중: 대형 컨테이너 카운터(코어 함수 셋 없음), 구독 감사(범위 미확정),
AE·CSE 삭제 시 '깨지는 구독' 미리보기(코어 함수는 왔음, 배포 986건).

### 2층 — 권한 (ACP)

**미완이 둘이다** — `acpi` 연결/해제, ACP 생성. 목표 ③의 절반이 아직 없다.

함께 지켜야 할 것: 잠그는 단위는 **AE 하나**(컨테이너·CIN 에는 못 붙이게 막는다),
`acpi` 최대 7개, 평가 순서 `ri` 오름차순, **생성자는 ACP 를 우회하므로 "완전히
잠갔다" 표시는 언제나 거짓**, 저장 전 simulate 필수(콘솔 origin 이
`usesuperuser` 라 자기가 만든 잠금을 자기 화면으로 못 느낀다).

### 3층 — 진단 (읽기 전용)

ACP 문제, **MySQL 세 값의 어긋남**(my.cnf / persist / 도는 값), 사용 이력,
카운터 불일치, ACP 변경 이력. 쓰기가 없으면 위험이 0 에 가깝다.

### 4층 — 설정 파일 (경계)

conf.json 노출 키 편집. 설계 근거는 없으나 사용자 직접 지시이고 이유가 실측으로
뒷받침된다(body limit 가 8년간 사실상 꺼져 있었다).

남은 위험: 적용 여부를 모른다는 것, 그리고 **저장 버튼만 `write.enabled` 에
묶여 있고 `POST /api/conf` 는 그 조건을 요구하지 않는다** — UI 를 우회하면
CSE 설정 없이 파일을 쓴다. 잠금이 아니라 표시일 뿐이다.

### 경계 밖 — 프로세스·인프라의 생사

기동·정지·재기동, MySQL `SET GLOBAL`, my.cnf, 백업/마이그레이션 실행.

밖인 이유: 설계 근거가 없고, 코어 계약이 없고, 인증이 다른 층과 같고, 관측이
포트·pid 까지뿐이며, 이미 다른 층과 상호 잠금을 일으켰다.

## 6. 뺄 것 (제안)

1. **고아 화면의 라이브 스캔** — 명시적 비목표 위반. 배치 결과를 읽는 형태로
   바꾼다.
2. **"리소스 트리"** 를 목표 문장에서 뺀다. 설계 스스로 보조 뷰로 강등했고
   CIN 은 트리 노드가 아니다. **다만 목표 ①을 "다시 적는다" 가 아니라 "아직
   안 지어졌다" 가 실상이므로, 문언 수정은 사용자 결정으로 올린다.**
3. **착수 금지 목록을 목표 문서에 박는다** — `subl` 계열(폐기 방향), 전역
   '유효 권한 없는 리소스' 큐, CIN 다중 선택 일괄 삭제, 상한 없는 CSV, 만료
   스캔 주기 제어. (전부 이미 비목표이거나 기결정인 것들이다.)
4. **새 화면보다 먼저 할 것을 순서로 고정한다** — 0층 위반 → 목표 ①②③의 미완
   → 안전장치 복구 → 그 다음에 대기 중인 화면.

## 7. 사용자가 결정해야 할 것

**① 서버 기동·정지·재기동을 남기는가.**
직접 지시하신 기능이라 내가 뺄 수 없다. (가) 그대로 두되 이 층만 별도 인증
(나) **재기동만 남기고 정지를 뺀다** — 목적이 "저장 후 적용" 이었으므로 재기동
이면 충분하고, 정지는 방치될 수 있는 유일한 동작 (다) 통째로 빼고 "재기동이
필요합니다" 안내까지만. **권고는 (나).**

**② 관리자 1명 전제를 유지하는가.**
설계 비목표 3이다. 이 전제 때문에 감사 로그에 '누가' 를 못 적고, MySQL 쓰기·
프로세스 제어·대량 삭제가 전부 여기 걸린다. 유지하면 셋은 영구히 못 연다.
푸는 순간 콘솔은 다른 제품이 된다.

**③ '쓰기는 전부 CSE 경유' 에 첫 예외를 여는가.**
대형 컨테이너 카운터 보정이 그 예외다. `cni/cbs` 는 oneM2M 읽기 전용이라 PUT
으로 우회하면 `st` 가 올라 없던 구독 알림이 나간다. 안 열면 유예된 7개
(cni 109만~593만) 화면은 만들 수 없다.

**④ 보존 정책(mni/mbs)을 콘솔이 다루는가.**
기본값이 사실상 꺼진 상태라, 낮추는 순간 다음 CIN 삽입에서 `delete_oldest` 가
수백만 건을 즉시 지운다. 되돌릴 수 없음의 규모가 다른 항목과 자릿수가 다르다.

**⑤ MySQL 읽기 화면을 1차로 만드는가.**
검토 결론은 "읽기는 지금 가능, 쓰기는 인증 선행" 이었다. **쓰기 범위는 읽기
화면을 실제로 보신 뒤에 정하는 것이 낫다** — 노출 후보표는 §2.8 에 있다.

**⑥ 구독 화면을 콘솔 범위로 확정하는가.**
설계에 없고 backlog 로 들어온 항목이다. 삭제 후보에는 **`broken` 만** 담고
`suspect`(3,452 중 1,028건 = 29.8%)와 섞지 않는다는 원칙은 이미 정해져 있다.
범위에 넣을지 자체가 결정 사항이다.

**⑦ 거부·attach 로그 화면을 기각하는가.**
내가 착수 금지로 넣으려다 뺐다 — **대가가 있다.** 이 화면이 없으면
`acpiAttachPolicy: 'creator'` 를 켤 판단 근거가 없어, **아무나 남의 리소스를
잠글 수 있는 상태**가 그대로 남는다(실측 200, 그 뒤 생성자 조회 403).

**⑧ 4층을 동결하는가.**
"코어의 '도는 값' 계약이 오기 전까지 설정 화면을 더 넓히지 않는다" 는 제안인데,
사용자가 직접 지시하신 유일한 영역의 확장 정지라 결정으로 올린다.

**⑨ `usesuperuser` 값 교체를 어느 배포 회차에 묶는가.**
그 문자열만 알면 모든 ACP 를 우회하는데 콘솔의 기본 origin 이 그 값이다.
콘솔 배포와 같은 회차여야 한다.
