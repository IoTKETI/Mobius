# ri / sri — 구조 주소를 키로 두는 설계와 그 위의 결함 넷

작성 2026-09-06. 배포 DB 실측(인덱스만 타는 질의)과 코드를 대조했다. 사용자 결정:
**설계는 유지하고 결함 넷을 고친다(A).** 키 교체(B)와 sri 폐지(C)는 하지 않는다.

## 1. 지금 어떻게 되어 있나

| 자리 | 값 | 예 (배포) |
|---|---|---|
| `lookup.ri` (PK · UNIQUE, `utf8mb3_bin`) | 구조 경로 `pi + '/' + rn` | `/Mobius/20230208-1/DATA/…` |
| `lookup.sri` (비유일 인덱스, `general_ci`) | 짧은 id. `ty-YYYYMMDDHHmmssSSS` + 난수 3자리. AE 는 `aei`, CSEBase 는 `5-…` | `4-20230208033333295373` · `SkzbCasUs6s` |
| `lookup.pi` / `spi` (`general_ci`) | 부모의 구조 경로 / 부모의 짧은 id | |

- **나갈 때** 응답 본문의 `ri` ← `sri`, `pi` ← `spi` (`responder.typeCheckAction`), 알림 `rep` 도 같다(`sgn.js`).
  알림 `sur` 와 discovery `uril` 은 구조 경로(CSE 상대) 그대로다.
- **들어올 때** 구조 URL 이면 `ri`, `/~/<cseid>/<id>` · `/<id>` 면 둘째 조각을 `sri` 로 보고
  질의 하나로 `ri = ? OR sri = ?` (`select_resource_from_url`). EXPLAIN 은 `index_merge union`.
- `acpi` · `mid` · ID 형 `nu` 는 `get_ri_list_sri`(whereIn sri) 로 경로로 바꾼다.
- 실사용: 접근 로그 이틀 390,877건 중 구조 주소 390,872건. 비구조 주소는 0 에 가깝다.

### 이 설계가 맞는 이유

구조 주소 조회가 PK 한 번이고 자식 목록·`la`/`ol` 도 `pi` 인덱스 하나다. oneM2M 에는
이름 변경·이동이 없어 materialized path 의 약점(하위 전부 갱신)이 없다.

## 3. 결정 — A: 설계는 두고 고친다

### A1. `sri` 생성기를 충돌 없게 (코드 + 마이그레이션 017)

새 모듈 `mobius/short_ri.js` 의 `generate(prefix)`:

```
<prefix>-<YYYYMMDDHHmmssSSS><pid base36 ≥5자><seq base36 3자>
예: 4-20260906031641123 + 00k3z + 001  → 4-2026090603164112300k3z001  (27자, 컬럼 45자)
```

- 시각 17자리는 유지한다(사람이 읽고, 시간순으로 정렬되며, 지금 도구가 그 접두로 센다).
- **한 호스트 안에서 구성적으로 유일하다** — pid 는 살아 있는 동안 유일하고, `seq` 는
  프로세스 안에서 같은 ms 에 증가한다. 시계가 뒤로 가도 `ms = max(now, last)` 로 단조라 반복이 없다.
  DB 하나를 두 호스트가 나눠 쓰는 배치는 지원하지 않는다(지금도 아니다).
- 쓰는 곳: `resource.js`(모든 타입) · `cb.js`(CSEBase). **AE 의 `aei` 도 같은 생성기**로
  `S`/`C` + 본문(`ty-` 접두 없이)을 만든다 — shortid 는 프로세스마다 카운터가 0 에서 시작해
  같은 초에 뜬 워커끼리 같은 id 를 낼 수 있다(`shortid.worker()` 를 안 불렀다). 길이 26자.
- 마이그레이션 `017-dedupe-lookup-sri`(수동): 중복 sri 묶음마다 `ct, ri` 순으로 첫 행을 남기고
  나머지에 새 sri 를 매긴다. 그 행에 자식이 있으면 자식의 `spi` 도 같이 바꾼다(`pi = 그 행.ri`).
  전수 `group by sri` 는 인덱스만 타지만 6,200만 행이라 분 단위다 — `timeoutMs: 0`.
- **UNIQUE 인덱스는 그 다음이다.** 중복이 0 이 된 뒤 `idx_lookup_sri` 를 UNIQUE 로 바꾸는
  DDL(INPLACE, 수십 분)을 점검 창에서 한다. 그 전까지는 생성기가 유일성을 지킨다.

### A2. 주소 해석을 가른다 (코드)

`get_target_url` 에서 첫 조각이 CSE base 이름이면 `sri` 를 넘기지 않는다 →
`select_resource_from_url` 이 `ri = ?` 만 던진다(PK, `type=const`). 비구조 주소는 지금처럼
둘 다 본다(0% 트래픽, 동작 동일). 배포 뒤 EXPLAIN 으로 `index_merge` 가 사라진 것을 본다.

### A3. 콜레이션을 맞춘다 (마이그레이션 018, 점검 창) — 범위 확대 (사용자 결정, 같은 날 저녁)

처음엔 `pi`·`sri`·`spi` 만이었다. 확인해 보니 "만드는 것" 은 oneM2M 대로 구분하는데(`ri` 가
PK) "찾는 것" 이 안 가렸다. 배포 실측: 대소문자만 다른 형제가 컨테이너 51쌍 · AE 9쌍 있고,
한 쌍의 자식이 `pi = ?` 로 섞인다(8 + 1 = 9). `?rn=` 필터는 대소문자를 안 가리고(이틀 115회),
`SmyAE` 가 있으면 `SMYAE` 는 409, `cr` 은 `fcnt` 만 bin 이었다. 사용자 결정: **식별자·이름은
전부 바이트 그대로 비교한다.**

018 의 대상: `lookup` 의 `pi`·`sri`·`spi`·`rn`·`lbl`·`acpi`, `ae.aei`, `cb.csi`, `csr.csi`/`cb`,
모든 표의 `cr`(information_schema 로 찾는다), `cin.pi`, `sub.pi`. `poa`·`nu` 는 주소라 둔다.
같은 재작성 안에서 `rn`·`sri`·`spi` 를 45 → 200 으로 넓힌다(A4 참조). lookup 과 cin 은 표 전체
재작성이라 **적용 시점은 사용자 결정**이고, 파일만 먼저 둔다(`autoApply` 없음).
눈에 보이는 변화 셋을 공지한다 — `?rn=` 은 정확히 맞아야 하고, 대소문자만 다른 aei 를 둘 다
받으며, 위 60쌍의 "남의 자식" 이 사라진다(그게 맞는 답이다).

### A4. 생성 시 길이 검사 (코드) — 한계는 oneM2M 이 아니라 이 CSE 의 저장소

oneM2M 은 길이를 정하지 않는다. 그래서 한계는 스키마의 것이고 실측이 그 한계가 좁다는 것을
보여 준다 — 구독 이름 최대 40자(30자 초과 2,023개), 지정 aei 는 `ae.aei` 200 인데 `lookup.sri`
45 에서 잘려 500. 그래서 018 이 `rn`·`sri`·`spi` 를 200 으로 넓히고, 코드는 넘었을 때 500 대신
400 으로 답하며 문구에 **"this CSE stores … up to N"** 이라고 적는다 — oneM2M 을 모르는
사용자일수록 "왜 안 되는지" 를 말해 줘야 대처한다. `rn` → `400-68`, 경로 → `400-69`, 지정한
AE-ID → `400-70`. 문구의 숫자는 `name_limits` 상수에서 만든다.

순서가 있다: 코드 한계는 배포 스키마(45/200/45)를 따르고, **018 을 적용한 뒤** 200/200/200 으로
올리는 커밋을 낸다. 코드가 스키마보다 앞서면 DB 가 500 을 낸다(`test/name-limits.test.js` 가
"넘지 않는다" 를 대조).

### A5. AE-ID 형식은 검사하지 않는다 (결정 기록)

`X-M2M-Origin` 이 정확히 `S`/`C` 일 때만 CSE 가 만들고 그 밖의 값은 그대로 `aei` 다.
사용자들이 oneM2M 을 몰라 "S/C 로 시작하지 않는다" 는 오류에 대처하지 못했고, 강제하면 만들 수
있는 id 가 제한된다. 배포에 그런 aei 가 13개 있다. 코드는 그대로이고 `ae.js` 주석과
`test/ae-id-policy.test.js` 로 결정을 잠근다.

## 4. 하지 않기로 한 것

- **B. 짧은 id(또는 정수)를 PK 로.** 보조 인덱스가 약 1/5 로 줄고 FK 도 가벼워지지만 `lookup` 79GB 와
  `cin` 249GB 를 다시 쓰고 조인을 전부 고쳐야 한다. 읽기는 지금도 O(1) 이라 얻는 것은 저장·캐시
  효율뿐이다. 재설치·대규모 재적재가 있을 때 다시 본다.
- **C. `sri` 폐지, 경로를 `ri` 로.** oneM2M(`ri` 는 비구조 id)에 어긋나고 `ri` 를 저장한 클라이언트가 깨진다.

## 5. 증명과 배포

- 생성기: 한 프로세스 20만 건 폭주·프로세스 4개 동시 폭주에서 중복 0, 접두·시각·길이·문자 집합.
  변이(난수 3자리로 되돌림)에서 폭주 시험이 실패해야 한다.
- 017: SQLite 임시 DB 에 중복 묶음(자식 있는 부모 포함)을 넣고 `up` → 중복 0, 첫 행 유지,
  자식 `spi` 갱신. 배포에서는 `--check` 로 묶음 수를 먼저 본다.
- A2: 옛 HEAD 와 URL 형태별(구조 · `/~/` · `/_/` · `/<id>` · la/ol · fopt · 없음) 차분 동일 +
  구조 URL 의 SQL 에 `sri` 가 없다(어댑터 tap).
- A4: 46자 이름 · 201자 경로가 4xx 로, 45·200 은 통과. `reason-catalog` 개수 95.
- 배포 순서: 코드(A1·A2·A4) → 017 `--check`/`--apply` → 재기동. 018 은 별도 창.
