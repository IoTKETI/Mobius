# 관리 콘솔 — 들어오는 것 추적

여러 세션이 같은 저장소에서 동시에 움직인다. 콘솔 화면을 확정해 놓으면 코어가
바뀌면서 화면이 뒤따라 깨지므로, **만들기 전에 무엇이 오는지 먼저 적어 둔다.**

이 문서는 살아 있는 목록이다. 다음 두 가지를 기록한다.

1. **감시 기록** — `lite` 에 들어온 변경 중 콘솔에 영향이 오는 것과, 그 판정
2. **대기 목록** — 지금 만들 수 있는 것 / 코어가 먼저 와야 하는 것 / 기각한 것

판정에는 근거를 붙인다. "그럴 것 같다" 로 화면을 만들면 없는 문제에 화면을
붙이게 된다 — 실제로 한 번 그럴 뻔했다(아래 §5 의 mobius4 건).

## 1. 현재 상태 (2026-08-30)

| | |
|---|---|
| 브랜치 | `feat/admin-console-part1` (`origin/lite` 를 전부 포함, 빨리감기 가능) |
| 테스트 | 682/682 |
| 화면 | 만료 · 고아 · 권한(문제/목록·상세/시뮬레이터/편집) |
| 쓰기 | 삭제 · `et` 연장 · 고아 정리 · ACP 저장 — **전부 oneM2M HTTP API 경유** |

콘솔은 별도 프로세스라 워커의 캐시 무효화 IPC 에 낄 수 없다. 그래서 읽기는 DB
직접이지만 쓰기는 반드시 CSE 를 지난다(`admin/cse.js`). 이 원칙이 아래 여러
항목의 가부를 가른다.

### 콘솔 함수를 만들어 주실 분들께

콘솔은 별도 프로세스이고 배포 `lookup` 은 5,740만 행이다. 두 제약이 따라온다.

- **워커 메모리에 닿지 못한다.** 워커가 메모리에만 들고 있는 집계는 콘솔이 읽을
  수 없다. DB 나 파일로 나와야 한다.
- **전역 `COUNT(*)`, 선행 와일드카드 `LIKE`, 인덱스를 못 타는 술어는 풀스캔이다.**
  상한을 둔 개수 세기 + 키셋 페이징으로 주면 좋다. 상한에 걸렸으면 조용히 자르지
  말고 `capped` 로 알려 준다 — 화면이 "여기까지가 전부" 로 보이는 것이 가장 나쁘다.
- 커서는 **불투명한 문자열 하나**로. 쪼갤 수 있는 커서는 언젠가 쪼개진다
  (실측: 두 조각 커서에서 한쪽만 넘겼더니 결과가 틀린 게 아니라 루프가 안 닫혔다).

| `06db502` | discovery 결과를 리소스별 ACP 로 거른다 | **시뮬레이터가 맞아졌다.** 아래 참고 |

### `06db502` — 시뮬레이터가 거짓말하던 것이 해소됐다

들어오기 전에 실측한 것:

```
잠근 곳 직접 조회/탐색 (제3자)   403
상위 AE 탐색 (제3자)            200, 4건 중 2건이 잠근 곳의 경로
콘솔 시뮬레이터                 DISCOVERY = 거부
```

시뮬레이터는 "거부" 라는데 상위 탐색에는 경로가 그대로 나왔다. 내용은 안 새고
**경로가 샜다**(이름·트리 구조·CIN 개수·생성 시각). 관리자가 화면을 보고
"잠갔다" 고 판단하면 틀리는 상태였다.

들어온 뒤 같은 시나리오: **누출 0건**, 시뮬레이터와 일치. 필터가 판정에
`security._evaluate_acp_rows` 를 그대로 쓰기 때문이다 — 시뮬레이터와 같은 함수라
원리적으로 갈리지 않는다.

> 남은 것: `conf.acpDiscoveryFilter` 를 `'off'` 로 두면 다시 새는데, 콘솔의
> `/api/session` 이 그 값을 안 내보낸다. §3-6.

## 3. 지금 만들 수 있는 것 — 코어 함수가 이미 있다

### 3-1. 구독 도달성 감사 화면 ★

`db_sql.audit_subscriptions(conn, opts, cb)` 가 `lite` 에 있고 **동작을 확인했다.**

```
nu_unresolved   /Mobius/nx_.../c1/watch   nu="/Mobius/vanished_..."
nu_bad_scheme   /Mobius/sa_.../c1/bad     nu="ftp://x/y"
scanCap=1 -> capped=true, next="/Mobius/.../ok_url"
```

사유 코드는 `db_sql.SUB_AUDIT_REASON` 으로 나온다 — 문자열을 화면에 복제하지 않는다.

화면이 말해야 하는 것 둘:

- **URL 형식 `nu` 는 이 감사가 판정하지 못한다.** 호스트가 죽었는지는 접속해 봐야
  안다. MQTT/WS 는 QoS0 라 브로커 도달조차 모른다 — **'판정 불가' 배지가 필요하고,
  MQTT 구독을 "안 쓰는 구독" 목록에 넣으면 안 된다.**
- `et` 는 이 목록에 없다(일부러 뺐다). `et` 는 런타임 어디에서도 강제되지 않아
  만료된 구독의 대다수가 지금도 정상 동작 중이다.

### 3-2. 만료 화면의 구독(ty=23) 경고 ★

`select_expired_page` 는 타입을 제외하지 않아 `ty=23` 이 필터 칩으로 그대로 뜨고,
골라서 일괄 삭제할 수 있다. 그런데 **`et` 가 지난 구독의 대다수가 지금도 정상
동작 중**이다(배포 표본에서 `et` 의 81% 가 이미 과거). 지금 화면은 "만료됨" 을
삭제해도 되는 신호처럼 보여 준다.

프런트만으로 된다 — 배너 · fate 라벨 교정 · 삭제 다이얼로그의 구독 경고.

### 3-3. ACP 신규 생성 + 대상에 붙이기

지금 쓰기는 `/api/acp/save`(기존 ACP 의 `pv`/`pvs` PUT) 하나뿐이다. `admin/cse.js`
에도 `create` 가 없다. 운영 방안이 정한 패턴 A/B/C 를 마법사로 두면 "예외 세
가지만 쓴다 · ACP 개수를 한 자리로 유지한다" 방침이 화면에서 지켜진다.
(템플릿 버튼은 편집 화면에 이미 있다 — `c031de6`)

### 3-4. 리소스 잠금 / 해제 — `acpi` 붙이기·떼기

운영 방안이 명시적으로 관리 UI 에 넘긴 항목이다. 붙이는 단위는 **AE 하나** —
컨테이너·CIN 에는 막아야 한다(상속되므로 붙일 이유가 없고, 붙이는 순간 관리
대상이 수만 개가 된다). 배포에 실제 대상이 있다: `/Mobius/sch8` 이 없는
`/Mobius/acp_sch1` 을 가리켜 잠겨 있다.

`acpi` 는 `varchar(200)` 이라 최대 7개다. 고르는 UI 여야 한다 — 서버가 오타를
막아 주기는 하지만(`400-63`), 손으로 적게 하면 그 400 을 화면에서 처음 만난다.

### 3-5. 전역 변경 이력 화면

`select_acp_audit` 은 `ri` 필터 없이도 부를 수 있는데 콘솔은 ACP 상세에서만
쓴다. `acpi_set`(리소스에 잠금을 걸고 푼 기록)은 ACP 상세에 안 보인다 — 그
리소스가 ACP 가 아니기 때문이다.

### 3-6. `/api/session` 에 `acpDiscoveryFilter` 노출

`mobius.js:133` 이 `global.acp_discovery_filter` 를 세운다. 콘솔의 `acp` 블록은
`observeMode/attachPolicy/defaultPolicy/audit/denyLog` 다섯만 내보낸다. `'off'`
면 잠근 곳의 경로가 다시 새므로 시뮬레이터의 `DISCOVERY` 판정이 보호를 과장하게
된다. 기존 블록과 같이 **설정값 기준**이라고 밝히면 된다.

### 3-7. 그 밖에

- 다중 `acpi` 는 OR 합집합이고 평가 순서는 `ri` 오름차순 — 화면도 그 순서로.
  정렬을 콘솔에서 다시 계산하면 MySQL 콜레이션과 갈릴 수 있으니, 코어가
  순서를 결과에 실어 주는 쪽이 안전하다.
- `acpAudit: 'off'` 일 때 "이력이 없습니다" 는 오표시다 — 끈 것과 없는 것은 다르다.
- 보존 정책(`mni`/`mbs`)이 사실상 꺼져 있다 — 판단할 화면이 없다.
- 컨테이너 `acpi` 증가 감시 — discovery 필터 성능 전제(`acpi` 가 채워진 리소스가
  배포에 2개)가 깨지는지.

## 4. 코어가 먼저 와야 하는 것

### 4-1. 대형 컨테이너 카운터 검증

인수인계 문서가 명시적으로 UI 에 넘겼는데(유예된 7개, `cni` 109만~593만) 착수할
수 없다.

- `reconcile_cnt_counters` 는 **드라이런이 없다** — 드리프트를 찾으면 즉시
  `update_cnt_cni` 로 UPDATE 한다. 조회 용도로 못 쓴다.
- 단건 지정 입구가 없다 — 커서 범위 스캔이라 `ri` 하나를 겨냥할 수 없다.
- 콘솔이 스윕을 돌리면 **안 된다.** `reconcile_running` 가드가 프로세스 로컬이라
  별도 프로세스인 콘솔은 그 바깥이고, 두 커서가 각자 전진하면 컨테이너를 건너뛴다.
- 유예/실패 목록이 `console.log` 로만 나가고 버려진다.
- **보정 쓰기 경로가 없다.** `cni`/`cbs` 는 oneM2M 에서 읽기 전용이고, PUT 경유는
  `st` 를 올려 없던 구독 알림을 낸다. 콘솔이 `update_cnt_cni` 를 직접 부르면
  워커 캐시가 낡는다 — "쓰기는 전부 CSE 경유" 의 첫 예외가 된다.

필요한 것: 읽기 전용 단건 집계 함수 · 유예 목록 조회 · 보정 쓰기 경로 결정.

### 4-2. 거부 이력 / 로그 조회

운영자가 "왜 막혔나" 를 물을 곳이 콘솔뿐인데 볼 방법이 없다. `[acp] deny` 는
`console.log` 로만 나가고, 저장소가 쓰는 유일한 로그 파일은 morgan 액세스 로그다.
`acp_observe.snapshot()` 은 워커 메모리에만 있고 콘솔이 닿지 못한다.

필요한 것: 파일 싱크 또는 감사 테이블. 표본 정책(`denyLog: 'sample'`, 초당 5줄)
때문에 기록이 전수가 아니라는 점도 화면이 말해야 하므로 함께 정해야 한다.

### 4-3. 구독 목록·상세

`select_sub` 은 부모별 조회뿐이라 전역 페이징 진입점이 없다.
필요한 것: `select_sub_list`(키셋 페이징, `{rows, more, next}`) ·
`select_sub_detail`. 목록 행에 `nu`·`enc` 를 붙일 때는 구독마다 읽지 말고
배치 `whereIn` 으로.

### 4-4. `subl` 계열 — **보류 권장**

`subl` 자체를 폐기하는 방향으로 결론이 났다(진실은 `sub.pi` 에 있고 FK CASCADE 가
정합을 보장한다). 곧 없어질 것에 화면을 붙이는 셈이라 착수하지 않는다.

배경: `update_lookup` 이 `subl` 을 절대값으로 덮어쓰고 호출부가 26곳이라,
구독을 동시에 만들면 조용히 사라진다(실측: 12개 동시 생성 → 부모 `subl` 에 1개).
사라진 것들은 리소스로는 살아 있는데 알림만 영영 못 받는다.

### 4-5. AE·CSE 삭제 전 "깨지는 구독" 미리보기

지금 삭제 다이얼로그는 **자손**만 경고한다. 지우는 리소스를 `nu` 로 가리키는
구독은 말하지 않는다. `audit_subscriptions` 에 `opts.targets` 를 더하는 쪽이
새 함수보다 낫다 — 같은 2단계 해석을 재사용한다.

## 5. 기각 — 다시 올라오지 않게

전수 조사에서 나온 뒤 **반증된** 것들이다. 근거를 남긴다.

| 주장 | 왜 아닌가 |
|---|---|
| discovery 필터가 콘솔을 틀리게 만든다 | 반대다. 콘솔 읽기는 DB 직접이라 필터를 안 타고, 필터가 시뮬레이터와 같은 평가 함수를 써서 오히려 맞아졌다 |
| 콘솔이 `resolve_acpi_entries` 를 안 불러 정상 참조가 미해결로 남는다 | `acp_lint.lint_acpi_refs` 가 내부에서 이미 부른다(`acp_lint.js:168`) |
| `select_lookup_acpi_in` 을 콘솔이 안 쓴다 | 소비자를 기다리는 export 가 아니라 `acp_filter` 의 내부 헬퍼다 |
| `select_sum_cbs`/`select_sum_ae` 가 미사용 | `app.js:1570/1580` 이 이미 서비스한다 |
| 관찰 모드 배지가 없다 | `App.vue` 가 이미 띄운다 |
| 마이그레이션 007 안내가 없다 | `admin/server.js` 가 503 + 적용 명령을 담아 준다 |
| `macp` 가드레일로 콘솔이 400 을 받는다 | 콘솔의 쓰기 본문에 `macp` 가 없다 |
| `[noti]` 로그로 알림 실패율 화면을 만든다 | 그 로그는 파일로 안 나간다. 코어 작업이지 콘솔 작업이 아니다 |

### mobius4 건 — 다른 저장소였다

`mobius4-c0` 세션이 상세한 지적을 보내왔으나 **다른 저장소**(`Workspace/mobius4`,
Sequelize/PostgreSQL/`hostingCSE.js`)를 보고 있었다. 이 저장소에는 `hostingCSE.js`
도 `int_cr` 도 없고, "`ty` 단독 인덱스 없음" 은 여기서 정반대다
(`mobiusdb.sql:342` 에 `idx_lookup_ty` 가 있다). 근거를 대고 확인 요청했고 상대도
확인 후 철회했다.

**교훈:** 다른 세션의 지적도 이 저장소의 코드로 확인하고 받는다. 그대로 반영했다면
없는 경합에 표류 감지를 붙이고, 없는 컬럼(`int_cr`)을 읽는 시뮬레이터를 만들 뻔했다.
