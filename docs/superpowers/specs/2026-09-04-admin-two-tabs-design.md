# 관리 콘솔 — 설정 탭 · 실행 탭 설계

- 작성일: 2026-09-04
- 대상 브랜치: `lite`
- 기준 커밋: `4a47c48` (프로토콜 프록시 3종 제거 직후)
- 범위: **모비우스 설정 탭**과 **모비우스 실행 탭** 둘뿐이다. 고아·만료·ACP·구독·리소스 탭은 이 문서가 다루지 않는다
- 선행 문서: [관리 콘솔 목표 재정의](2026-09-01-admin-console-purpose.md), [관리 콘솔 설계](2026-08-28-admin-console-design.md)

> ## 기조
>
> **터미널에서 실행하거나 `conf.json`·`mobius.js` 를 직접 고치는 길은 그대로 둔다.
> 다만 평상시에는 관리 UI 의 두 탭만으로 띄우고 지켜볼 수 있어야 한다.**
>
> 이 문장이 이 설계의 모든 판단 기준이다. "UI 로도 되고 터미널로도 된다" 가 아니라
> **"UI 가 평상시 경로이고, 터미널은 남겨 둔 비상구"** 다.

## 0. 요약

두 탭이 **DB 를 아예 치지 않는다.** 읽는 것은 `conf.json`, 부팅 기록, 로그 파일, 그리고 포트뿐이다.
누적 저장도 하지 않는다 — `admin.db` 도, 메트릭 저장소도, 추이 그래프도 만들지 않는다.

바꾸는 것은 다섯이다.

| | 무엇 | 어디 |
|---|---|---|
| 1 | 소스에 박힌 설정 9개를 conf 키로 내린다 (`mobius.js` 8 + `app.js` 1) | `mobius/conf_schema.js` · `mobius.js` · `app.js` |
| 2 | 포트 4개를 화면에 열고, 죽은 키 1개를 지운다 | `conf_schema.js` 의 `exposed` |
| 3 | 기동 시 적용된 설정을 파일에 한 줄 남긴다 | `mobius.js` · `mobius/boot_record.js`(신설) |
| 4 | **실행 지식을 모듈 하나로 떼어내** 콘솔과 CLI 가 함께 쓴다 | `tools/mobius-ctl.js`(신설) · `admin/process_ctl.js` 삭제 |
| 5 | 실행 탭을 만들고, 설정 값의 3상태를 구분한다 | `admin/` 백엔드 · `admin/web/src/` |

여기에 **코어 쪽 전제 조건 둘**이 붙는다. 둘 다 두 탭 밖의 파일이지만 없으면 실행 탭이
성립하지 않는다.

- `app.js` 의 `cluster.setupPrimary({ windowsHide: true })` — 없으면 Windows 에서 워커 수만큼
  콘솔 창이 뜬다(§8.1)
- **포트 충돌 처리** — 없으면 중복 실행이 좀비가 되고 pm2·포트 확인 둘 다 정상으로 보인다(§4.8)

## 1. 범위와 경계

### 1.1 넣는 것

위 표의 다섯 가지. 화면은 **설정 탭**(기존 `ConfView` 개선)과 **실행 탭**(신설) 둘이다.

### 1.2 빼는 것

- **sub 탭 · 리소스 탭** — 새 코어 조회 함수가 선행이고, 리소스 탭은 `hit_ri` 까지 얽혀 그 자체로 한 사이클이다
- **기존 만료·고아·ACP 탭 정리** — 0층 위반 4건 포함. 이번 것과 겹치지 않으므로 따로 잡는다
- **일괄 작업 안전장치 · `admin.db`** — 삭제를 다루는 화면에 붙는 것이라 리소스 탭과 함께 간다
- **콘솔 자신의 MySQL 풀 설정(100/0)** — 두 탭이 질의를 안 하므로 지금은 놀고 있다. 실제로 DB 를 치는 탭을 만들 때 다룬다

### 1.3 경계에서 정한 것

**콘솔 자신의 설정 7키를 `conf_schema` 로 올린다.**
`adminPassword`·`adminPort`·`adminHost`·`adminCseHost`·`adminCsePort`·`adminOrigin`·`adminPm2Name` 은
지금 코어 스키마 밖이라 화면에서 편집이 안 된다. 올리되 `adminPassword`·`adminOrigin` 은 `secret` 으로 둔다.

> 헌장(`2026-08-28-phase2-charter.md:588`)이 "콘솔 전용 origin 은 안 만든다"로 기각한 것은
> **새 마스터 키를 만드는 것**이지 기존 키를 화면에서 관리하는 것이 아니다. 그 해석으로 진행한다.

**pm2 모드만 지원한다.** detached spawn 폴백을 남기지 않는다(§4.1).

**`npm start` 를 감독 받는 경로로 바꾼다.** 직접 실행은 `npm run start:direct` 로 남긴다.
기조가 "웬만하면 감독 받는 쪽"이므로 기본값이 그쪽이어야 한다. `run_*.bat` 셋도 같이 고친다.

**직접 실행을 막지 않는다.** 중복 실행 좀비의 원인은 실행 방법이 아니라 포트 충돌 미처리이고,
그것은 §4.8 에서 코어를 고쳐 해결한다.

## 2. 설정을 conf 로 내린다

### 2.1 지금 설정이 어디에 흩어져 있나

실측(2026-09-04, 콘솔을 띄워 확인):

| 어디 | 개수 | 화면에 |
|---|---|---|
| `conf.json` — 스키마에 선언되고 `exposed` | 14 (권한 7 · 요청 처리 2 · 저장소 5) | **보임** |
| `conf.json` — 선언은 됐지만 `exposed: false` | 5 (포트 3 + 비밀 2) | **안 보임** |
| `mobius.js` 상단 하드코딩 (`global.*`) | 8 | **`conf.json` 에 존재하지 않음** |
| `app.js` 하드코딩 (`usespid`) | 1 | **`conf.json` 에 존재하지 않음** |
| 콘솔 자신의 키 (`admin*`) | 7 | 스키마 밖이라 안 보임 |

안 보이는 5개 중 셋이 **포트 전부**(`csebaseport`·`sgnManPort`·`hitManPort`)다.
`group: '네트워크'` 로 분류까지 되어 있는데 `exposed: false` 라 `describe()` 가 걸러내므로
**화면에 네트워크 분류 자체가 없다.**

> **기준선 주의.** 이 문서를 쓰는 도중 `4a47c48` 이 프로토콜 프록시 3종(`pxy_mqtt.js`·
> `pxy_ws.js`·`pxy_coap.js`)과 `wdt.js` 를 지웠고, 그와 함께 conf 키 `pxyWsPort`·`pxyMqttPort`
> 도 빠졌다(전체 21 → 19키). 아래 표와 근거는 **그 이후 기준**이다. §7.3 이 경고한
> "다른 세션과 겹친다"가 문서 작성 중에 실제로 일어난 사례다.

### 2.2 위험 3등급

전부 편집 가능하게 두지 않는다. `usecsebase` 를 추적한 결과가 그 이유다.

```
mobius/cb.js:36-37      CSEBase 의 ri = '' + '/' + 'Mobius'  =  /Mobius
mobius/resource.js:871  자식은  ri = pi + '/' + rn
```

즉 **저장된 모든 경로가 `/Mobius/…` 로 시작한다.** 값을 바꾸면 `cb.js` 의 조회가 실패해 그 자리가 CSEBase 행을 하나 더 만들고 기존 트리 전체가 고아가 된다. 거기에 discovery 의
`whole_tree` 최적화(`sql_action.js` 의 `build_descendant_sql`)가 어긋나고, `fopt.js` 가 기존 멤버를 원격 CSE 로
오판해 **조용히 건너뛴다**. 확인 관문으로 감쌀 수 있는 종류가 아니다.

| 등급 | 뜻 | 스키마 |
|---|---|---|
| **편집** | 그냥 저장 | 평범 |
| **관문** | 저장 전에 "무엇이 깨지는가"를 문장으로 보이고 타이핑 확인 | `danger` 표시 + 기존 `ConfirmDialog` 재사용 |
| **읽기** | 값만 보이고 저장 거부 | `readOnly: true` (`conf_schema.validate` 가 막는다) |

### 2.4 `conf_schema` 규약이 요구하는 것

`test/conf-schema.test.js` 를 읽고 확인한 것들이다. 새 키를 넣을 때 같이 해야 한다.

1. **`mobius.js` 가 `conf.<키>` 를 실행 코드로 읽어야 한다.** 테스트의 키 스캐너가 `mobius.js` 만
   훑고 주석을 걷어낸다. `app.js` 에서만 읽으면 "표에 있는데 아무도 안 읽는 키"로 걸린다 —
   `spId` 를 옮기는 이유다.
2. **기본값을 세 가지 작성 모양 중 하나로** 쓴다. `? conf.K : 리터럴;` / `conf.K || 리터럴;` /
   `함수(conf.K, 리터럴)`. 다른 모양이면 `dflt` 대조가 **조용히 건너뛰어진다**.
3. **새 group 3개**(`CSE 신원`·`접근 제한`·`콘솔`)를 `test/conf-schema.test.js` 의 `KNOWN`
   목록에 넣는다.
4. `apply: 'reload'` 인 키는 `reloadWith` 도 반드시 준다. 이번 새 키에는 해당 없음.

덤으로 하나 고친다 — `mobius.js` 의 `use_mqtt_port = '8883'` 대입은 `global.` 접두가 없는
**암묵 전역 대입**이다(파일에 `'use strict'` 가 없어서 동작한다). 명시적으로 바꾼다.

## 3. 지금 도는 값 / 파일 값 / 재기동 필요

### 3.1 지금 `apply` 배지는 화면에서 거짓이다

`conf_schema` 의 `apply` 는 이런 뜻이다.

| `apply` | 뜻 |
|---|---|
| `runtime` | 요청마다 `global.*` 을 읽는다 — **값만 바꾸면** 즉시 먹는다 |
| `reload` | 모듈이 캐시한다. 재설정 함수를 불러야 한다 |
| `restart` | 기동 시 한 번 읽는다 |

여기서 "값"은 **`global.*`** 이지 `conf.json` 이 아니다. `mobius.js` 는 기동 때 한 번 파일을 읽어
전역에 심고 그 뒤로는 파일을 다시 안 본다. **콘솔은 파일만 고친다.** 즉 콘솔이
`acpDiscoveryFilter` 를 바꾸고 화면이 "즉시 반영" 배지를 띄워도 도는 Mobius 는 옛 값 그대로다.

유일한 예외가 오히려 더 나쁘다 — `cluster.fork()` 가 `mobius.js` 를 다시 실행하므로
**죽었다 되살아난 워커만** 새 값을 읽는다. 재기동 없이 파일만 고치면 워커마다 값이 갈린다.

`apply` 자체는 코어의 성질이므로 그대로 둔다. **화면이 말하는 것을 바꾼다** —
"이 값이 지금 도는 프로세스에 닿았는가".

### 3.2 부팅 기록 — `log/mobius-boot.jsonl`

`mobius.js` 가 전역을 다 세운 뒤, `require('./app')` 직전에 한 줄 남긴다.

```jsonl
{"role":"master","pid":8812,"at":"2026-09-04T01:20:03.114Z","conf":{"db":"mysql","cseBase":"Mobius",...}}
{"role":"worker","pid":8840,"at":"2026-09-04T01:20:04.902Z","conf":{...}}
```

- **`secret: true` 인 키는 뺀다.** 대상 목록을 `conf_schema.all()` 에서 secret 을 걸러 만들므로
  **새 비밀 키가 생겨도 자동으로 빠진다.** 손으로 유지하는 목록을 만들지 않는다
- 값은 `conf` 원본이 아니라 **실제로 전역에 심긴 값**이다. 파일에 없어 기본값이 쓰였거나
  `argv[2]` 가 `conf.db` 를 이긴 경우까지 사실대로 남는다
- **마스터가 기동 때 파일을 비우고, 이후 전원이 append.** 파일은 항상 "지금 이 판"만 담는다.
  워커 24~26개 + 가끔의 재생성이면 크기는 무시할 수준이다
- **줄 수에 상한을 둔다(예: 워커 수 × 3).** 상한이 없으면 재포크 루프(§4.8)에서 워커가
  초당 24줄씩 append 해 **하루 수백 MB** 로 자란다. 상한에 닿으면 더 쓰지 않고
  `{"role":"capped", ...}` 한 줄만 남긴다 — 그리고 **그 줄이 곧 재포크 루프 탐지 신호**가 된다.
  짧은 시간에 상한을 넘겼다는 것은 워커가 계속 죽고 있다는 뜻이다
- **pm2 밖에서 떴으면 그 사실을 남긴다**(`process.env.pm_id` 부재). 콘솔이 이것을 읽어
  "정지·재기동을 할 수 없다"를 표시한다

**파일을 고른 이유** — pm2 여부와 무관하기 때문이다. stdout 은 pm2 가 가져가지만 이 파일은
Mobius 자신이 쓴다. 기계가 읽는 채널과 사람이 읽는 채널을 분리한다.

### 3.3 판정

키마다 세 갈래로 답한다. 근거는 **mtime 이 아니라 값 대조**다 — 어느 키가 다른지까지
말할 수 있어야 한다. mtime 은 "기록보다 파일이 새로운가"의 보조 신호로만 쓴다.

| 상태 | 조건 | 화면 |
|---|---|---|
| **적용됨** | 파일 값 = 마스터 기록 값 | 조용함 |
| **재기동 대기** | 파일 값 ≠ 마스터 기록 값 | 그 행에 표시 + 탭 상단에 "재기동 대기 N건" |
| **모름** | 기록 파일이 없거나 Mobius 가 안 떠 있음 | "지금 도는 값을 확인할 수 없습니다" — 값 대조를 **아예 하지 않는다** |

여기에 네 번째 경고를 단다.

> **워커 불일치** — 기록의 워커 줄들이 서로 다른 값을 갖고 있다. 재기동 없이 파일이 바뀐 뒤
> 일부 워커만 되살아난 상태다.

지금은 아무도 못 보는 상태이고, 실제로 일어날 수 있는 일이다.

### 3.4 오류 처리

- **기록 파일이 없다** → "모름". 콘솔이 만들지 않는다. Mobius 가 이 콘솔 밖에서 떴거나
  구버전이라는 뜻이고, 그 사실을 그대로 말한다
- **기록이 깨졌다** → 깨진 줄만 버리고 나머지로 판정. 전부 깨졌으면 "모름"
- **`conf.json` 이 깨졌다** → `mobius.js` 와 같은 원칙을 따른다. **덮어쓰지 않고** 화면에
  "파일이 깨져 있다 — 고치기 전에는 저장할 수 없다"를 띄운다
- **기록에는 있는데 스키마에 없는 키** → 옛 판으로 뜬 Mobius 다. 그 키는 대조에서 빼고
  "기록이 오래됐다"만 표시

## 4. 실행 탭

### 4.1 실행 방식 — 실행 지식을 모듈 하나로 떼어낸다

**실행 지식은 콘솔의 것이 아니다.** 콘솔 안에 두면 터미널 사용자는 같은 일을 다른 방법으로
해야 하고, 그러면 두 길이 어긋날 여지가 계속 남는다. 그래서 떼어낸다.

```
        npm start / npm run mobius:*          관리 UI [기동]
                    │                                │
                    └────────────┬───────────────────┘
                                 ▼
                      tools/mobius-ctl.js       ← 실행 지식은 여기 하나뿐
                       · 앱 이름 · 스크립트 경로
                       · exec_mode 'fork' · instances 1
                       · 기동 전 포트·pm2 상태 확인
                       · pm2 API 호출
                                 ▼
                              pm2 데몬
                                 ▼
                           node mobius.js
```

이 분리가 주는 것 넷:

1. **콘솔로 하든 터미널로 하든 같은 코드를 지난다.** 결과가 갈릴 수 없다
2. **기조가 구조로 성립한다** — "어느 쪽을 써도 같다"가 말이 아니라 사실이 된다
3. **`pm2 start <이름>` 모호성이 사라진다**(§8.2). 이름·경로·모드를 모듈이 갖는다
4. **중복 실행 방어가 한 곳이다**(§4.8). 두 경로가 동시에 보호된다

`admin/` 은 이 모듈을 `require` 한다. `mobius/` 안에 두지 않는다 — **코어는 자기가 어떻게
띄워졌는지 몰라야 한다.** 의존 방향은 `mobius-ctl → pm2`, `admin → mobius-ctl` 이고
코어는 어느 쪽도 모른다.

**pm2 는 `package.json` 의존성으로, 배포와 같은 `6.0.14` 로 핀한다.**
셸도 PATH 탐색도 명령 문자열 조립도 없다.

#### npm 스크립트

```json
"start"         : "node tools/mobius-ctl.js start",     ← 감독 받는 경로가 기본
"start:direct"  : "node mobius.js",                     ← 감독 없는 직접 실행
"mobius:stop"   : "node tools/mobius-ctl.js stop",
"mobius:restart": "node tools/mobius-ctl.js restart",
"status"        : "node tools/mobius-ctl.js status",
"admin"         : "node tools/mobius-ctl.js admin"
```

`npm start` 를 감독 경로로 바꾼다. "웬만하면 감독 받는 쪽"이 기조이므로 기본값이 그쪽이어야
한다. 직접 실행은 없애지 않고 `start:direct` 로 남긴다.
`run_mobius.bat`·`run_sqlite.bat`·`run_mysql.bat` 셋도 같이 고친다.

`npm run status` 는 **콘솔이 읽는 것과 똑같은 것**(pm2 목록 · 포트 · 부팅 기록)을 터미널로
찍는다. 브라우저를 안 열고도 "지금 돌고 있나"를 확인할 수 있어야, 잊고 또 띄우는 일이 준다.

| | CLI 를 셸로 부르기 | 프로그래매틱 API |
|---|---|---|
| 설치 | 전역 설치 필요 → 권한·PATH 문제 | **의존성.** `npm install` 로 딸려 옴 |
| PATH | `where pm2` 로 찾아야 함 | 무관 |
| 명령 모호성 | `pm2 start Mobius` 가 **경로로 해석돼 엉뚱한 걸 띄웠다**(§8.2) | 없음 — 객체로 `script` 를 명시 |
| 상태 조회 | 요청마다 `execFile` | IPC 직접 호출 |
| 에러 | exit code + stderr 파싱 | 구조화된 err 객체 |

전역 설치가 필요 없으니 **"pm2 가 없으면 어떡하나"라는 문제 자체가 없어진다.**
설치 버튼도, 권한 실패 처리도, "콘솔을 재시작하세요" 안내도 필요 없다.

**버전을 6.0.14 로 핀하는 이유** — 배포 데몬이 6.0.14 다(§8.4). 7.x 모듈로 붙으면
버전 불일치가 난다. 나중에 배포 pm2 를 올리면 핀도 같이 올려야 하므로 그 사실을
`admin/README.md` 에 적는다.

**detached spawn 폴백을 남기지 않는다.** 두 방식이 공존하면 화면이 모드별로 되는 것과
안 되는 것을 설명해야 하고, `ours` 판정(§8.3)이 되살아난다. `admin/process_ctl.js` 는 삭제한다.

### 4.2 안전 — 이름 하나만 만진다

배포 데몬에 앱이 17개 있고 Mobius 는 그중 하나다(§8.4). 이것이 §4 의 첫 번째 규칙이다.

```js
// conf.adminPm2Name 하나만 다룬다. 다른 이름은 이 모듈을 통과하지 못한다.
function guard(name) {
    if (name !== TARGET) { throw new Error('이 모듈은 ' + TARGET + ' 만 다룬다'); }
}
```

- `list()` 결과는 **그 이름으로 걸러서** 화면에 올린다. 남의 앱은 보여 주지도 않는다
- `start`/`stop`/`restart` 는 상수 `TARGET` 만 인자로 받는다. 화면에서도 CLI 에서도
  이름을 받지 않는다
- **`delete` 는 아예 구현하지 않는다.** 앱 등록 해제는 이 모듈이 할 일이 아니다

### 4.3 화면

```
┌─ 상태 ────────────────────────────────────────────────────┐
│ ● 돌고 있다   pid 247395 · 9시간 4분 · 워커 24 · 재시작 13회 │
│                                    [정지] [재기동]         │
│ ⚠ 재기동 대기 3건 — 파일이 바뀌었지만 반영되지 않았다        │
└───────────────────────────────────────────────────────────┘
┌─ 최근 (액세스 로그 끝 64KB) ──────────────────────────────┐
│  요청 812   초당 13.9   2xx 98.2%  4xx 1.6%  5xx 0.2%     │
│  1초 초과 7건        중단된 요청 2건        [갱신]         │
└───────────────────────────────────────────────────────────┘
┌─ 로그 ────────────────────────────────────────────────────┐
│ [액세스] [Mobius 출력] [오류]   날짜 ▾   □ 따라가기        │
└───────────────────────────────────────────────────────────┘
```

**열어 두기만 하면 도는 것은 포트 확인 하나뿐이다.** 요약은 화면에 들어올 때 1회 + [갱신] 버튼,
로그는 "따라가기"를 켰을 때만 5초 폴링한다.

**재시작 횟수**는 pm2 가 `restart_time` 으로 주므로 우리가 아무것도 모으지 않고 얻는다.
이것이 없으면 "밤새 몇 번 죽었는지"를 알 방법이 없다.

### 4.4 상태의 세 출처

| 출처 | 주는 것 |
|---|---|
| `pm2.list()` | status · pid · uptime · **restart_time** · memory · cpu · 로그 경로 |
| `log/mobius-boot.jsonl` | 어떤 설정으로 떴는가 · 워커 수 · 워커 불일치 |
| 포트 `connect` | **정말 받고 있는가** |

셋을 다 본다. pm2 가 `online` 이라 해도 포트를 열었다는 뜻은 아니다 — 배포의 `47e3a7e`
"DB 커넥션을 못 얻으면 포트 없이 살아 있던 것"이 정확히 그 상황을 고친 커밋이다.

**그리고 "pm2 online + 포트 열림"도 정상을 뜻하지 않는다.** 중복 실행 좀비(§4.8)가 정확히
그 모양이다 — 포트는 먼저 뜬 쪽이 쥐고 있고, 두 번째 마스터는 살아 있어 pm2 가 `online` 으로
본다. 그래서 판정에 넷째 규칙을 둔다.

| 판정 | 근거 |
|---|---|
| **정상** | pm2 `online` + 포트 열림 + 부팅 기록의 워커 줄이 안정 |
| **좀비 의심** | 위 둘은 맞는데 부팅 기록이 `capped` 이거나 워커 줄이 계속 늘어난다 |
| **pm2 밖** | 포트는 열렸는데 pm2 목록에 없다. 부팅 기록이 `pm_id` 부재를 말한다 |
| **떠 있지만 못 받음** | pm2 `online` 인데 포트가 닫혀 있다 |

### 4.5 로그

- 경로는 **`pm2.list()` 가 준 것**을 쓴다(`pm_out_log_path`·`pm_err_log_path`). 추측하지 않는다
- **out 과 error 를 나눠 보여 준다.** 배포 error 로그가 하루 3~5MB 로 out 보다 크다
- **회전본을 같이 다룬다.** 배포에 `pm2-logrotate` 가 이미 돌고 있어(10M/10개/매일 0시)
  `Mobius-out__2026-09-04_00-00-00.log` 형태로 밀린다. 날짜 선택 목록에 그 파일들을 올린다
- 액세스 로그는 `log/access-YYYYMMDD.log`. 배포 기준 하루 53~71MB 이므로 **끝 64KB 만** 읽고
  화면에 "최근 N줄 기준"을 명시한다
- 원문 내려받기 링크를 두되 **파일 크기를 먼저 표시한다**
- **`source` 는 열거값만 받는다**(`access` · `stdout` · `stderr`). 경로 문자열을 받으면
  콘솔 비밀번호 하나로 임의 파일 읽기가 된다

**액세스 로그 파서는 마지막 필드의 `-` 를 0으로 세지 않는다.** 중단된 요청은 그 필드가 `-` 이고
(morgan 이 `res._startAt` 을 `onHeaders` 로 채우는데 헤더를 못 보낸 요청에는 그 시점이 없다),
숫자로 강제 변환하면 **가장 나쁜 요청들이 통째로 빠진다**. `-` 를 별도 카운터로 센다.

### 4.6 오류 처리

- **pm2 데몬이 없다** → API 가 데몬을 띄운다. 그 사실을 화면에 알린다
- **버전 불일치** → `pm2.connect` 가 경고를 낸다. 화면에 그대로 노출하고 진행하지 않는다
- **`online` 인데 포트가 안 열림** → "떠 있지만 요청을 못 받는다"로 구분해 말하고,
  `error` 로그 마지막 줄을 함께 보여 준다
- **일괄 작업 때문에 막힘** → `guard_busy` 가 409 를 낼 때 "작업 X 때문에 막혀 있다 · [작업 보기]"
  로 말한다. 상호 잠금 자체를 고치는 것은 이번 범위 밖이다
- **콘솔 자신이 죽음** → `uncaughtException`/`unhandledRejection` 을 로그에 남기고 종료한다.
  살리지 않는다 — 코어 `backstop.js` 와 같은 판단이다

### 4.7 전제 조건 — `app.js` 한 줄

```js
cluster.setupPrimary({ windowsHide: true });   // fork 루프 앞. Linux 에서는 무시된다
```

두 탭 밖의 파일이지만 **이것이 없으면 Windows 에서 실행 탭을 쓸 수 없다.** 실측 근거는 §8.1.

### 4.8 중복 실행 — 지금은 좀비가 된다

실측으로 확인한 것이다(§8.7). 이미 7579 를 누가 쥔 상태에서 Mobius 를 또 띄우면:

```
워커    EADDRINUSE → listen 에 .on('error') 가 없어 uncaught 로 던진다
        backstop 이 잡아 워커만 종료 (마스터는 살린다)
마스터  cluster.on('exit') → 재포크 → 또 EADDRINUSE → 무한 반복
        실측 12초에 워커 사망 20회 이상
pm2     마스터가 안 죽으니 status online · restart_time 0 — 정상으로 본다
```

`app.js` 의 `fail_start` 는 이걸 안 잡는다 — 호출부 6곳이 전부 **DB 연결 실패 경로**다.
그리고 **cluster 가 아닌 단일 프로세스였다면** pm2 가 재시작하다 `errored` 로 포기했을 것이다
(실측). Mobius 는 마스터가 살아 있어서 그 안전장치가 작동하지 않는다.

현실적인 경로는 이렇다 — **관리 UI 에서 띄우고 브라우저를 닫는다. 돌고 있다는 사실을 잊는다.
터미널에서 또 띄운다.** 브라우저를 닫아도 Mobius 는 계속 돌지만, 사람의 기억은 닫힌다.

방어를 셋 둔다.

**(가) `tools/mobius-ctl.js` 가 기동 전에 확인한다.** 포트와 pm2 상태를 먼저 보고,
이미 돌고 있으면 띄우지 않고 그 사실을 말한다. 콘솔과 CLI 가 동시에 보호된다.

**(나) `mobius.js`/`app.js` 자체 방어 — 마지막 방어선.** 모듈을 안 지나는
`npm run start:direct` 경로가 있으므로 코어에도 있어야 한다.

- 기동 전 포트 확인 → 열려 있으면 뜨지 않고 `[기동 거부]` 로 안내
- `listen` 에 `.on('error')` → `EADDRINUSE` 면 워커가 **예약 종료 코드**로 나가고,
  마스터는 `cluster.on('exit')` 에서 그 코드를 보면 **재포크하지 않고 자기도 종료**한다.
  워커만 죽이면 3초 느린 루프가 될 뿐이다

**(다) 화면과 CLI 가 상태를 먼저 본다.** `pm2 start <이름>` 은 이미 `online` 인 앱에
불러도 거부가 아니라 **재시작**이다(실측 §8.7). pm2 가 안 막아 주므로 우리가 막는다 —
`online` 이면 [기동] 을 비활성화하고 "이미 돌고 있습니다 · 재기동하려면 [재기동]" 으로 안내한다.

여기에 **경고 한 줄**을 더한다. `mobius.js` 가 pm2 밖에서 떴으면(`process.env.pm_id` 부재)
그 사실을 로그와 부팅 기록에 남긴다. 콘솔이 그것을 읽어 "pm2 밖에서 돌고 있다 —
정지·재기동을 할 수 없다"를 표시한다.

> **직접 실행을 막지 않는다.** 좀비의 원인은 "터미널로 띄웠다"가 아니라 "포트 충돌이
> 처리되지 않았다"이다. 막아도 pm2 안에서 중복이 생기면 똑같이 좀비가 되고, 대신
> `npm run start:direct`·`node --inspect`·비상 시 탈출구를 잃는다.

## 5. 시험 계약

`test/conf-schema.test.js` 가 이미 19건으로 conf 키를 양방향 강제하므로 **새 키 16개**(소스에서
내리는 9개 + 콘솔 7개)**는 자동으로 거기 걸린다.** 새로 쓰는 것은 그 표가 못 잡는 것들이다.

### 5.1 코어

**① 빈 `conf.json` 으로도 지금 동작이 그대로다** ← 배포 안전의 핵심

`dflt` 대조는 "리터럴이 같은가"만 본다. 보장해야 하는 것은 **"배포 `conf.json`(5키)에 아무것도
안 넣어도 동작이 안 바뀐다"** 이다. 빈 conf 로 `mobius.js` 를 로드해 전역을 직접 확인한다.

```
usecsebase 'Mobius' · usecseid '/Mobius2' · usespid '//keti.re.kr'
use_mqtt_broker 'localhost' · use_secure 'disable' · use_mqtt_port '1883'
uservi '2a' · allowed_ae_ids [] · allowed_app_ids []
```

**② `spId` 를 `mobius.js` 가 세우고, 콘솔은 하드코딩하지 않는다**
`app.js` 의 옛 자리가 안 남아야 하고, `admin/server.js` 가 같은 값을 두 번째로
박아 둔 것도 없어져야 한다.

**③ `useSecure='enable'` 이면 `mqttPort` 가 8883 이 된다**

**④ 부팅 기록** — 마스터가 비우고 워커가 append / **`secret` 키가 안 들어간다**(새 비밀 키를
하나 추가해도 자동으로 빠지는지) / 값이 `conf` 원본이 아니라 실제 전역 값

**⑤ `cluster.setupPrimary({ windowsHide: true })` 가 fork 앞에 있다**
Linux CI 에서는 증상이 안 나오므로 소스 검사로 잡는다. 다만 이 저장소에는 전례가 있다 —
`test/admin-process-ctl.test.js` 가 소스 문자열만 봐서 **머리말 주석만으로 통과**했다.
그래서 **주석을 걷어낸 뒤** 검사한다.

**⑥ 포트 충돌이 좀비를 만들지 않는다** — 워커가 `EADDRINUSE` 로 죽을 때 마스터가
**재포크하지 않고 종료**하는지. 실제로 포트를 잡아 두고 띄워서 확인한다. 지금은 무한
재포크가 되므로(§8.7) 이 시험은 **처음에 반드시 실패해야 한다.**

**⑦ 부팅 기록에 상한이 걸린다** — 워커가 상한을 넘겨 append 하려 하면 `capped` 한 줄만
남고 파일이 더 안 자라는지.

### 5.2 실행 모듈과 콘솔

**⑧ `mobius-ctl` 이 이름 하나만 만진다** ← 배포에 남의 앱 16개가 있어 제일 중요
`start`/`stop`/`restart` 가 `TARGET` 외 이름으로 호출되지 않는다 / `list()` 가 걸러진다 /
`delete` 가 export 되지 않는다

**⑨ 콘솔과 CLI 가 같은 모듈을 지난다** — 두 경로가 실행 지식을 각자 갖지 않는지.
`admin/` 안에 pm2 를 직접 부르는 코드가 없어야 하고, CLI 도 마찬가지다.

**⑩ 이미 돌고 있으면 기동하지 않는다** — `online` 상태에서 `start` 를 부르면 띄우지 않고
그 사실을 돌려준다. pm2 는 이 경우 **재시작**해 버리므로(§8.7) 모듈이 막아야 한다.

**⑪ 3상태 판정** — 같으면 적용됨 / 다르면 재기동 대기 / 기록 없으면 **대조 자체를 안 하고** 모름 /
워커 줄이 서로 다르면 불일치 경고 / 기록에 있는데 스키마에 없는 키는 대조에서 뺀다

**⑫ 액세스 로그 파서가 `-` 를 0으로 안 센다** — 실제 형식의 줄로 시험한다

**⑬ 로그 tail 이 `source` 열거값 밖을 거부한다**

**⑭ 새 라우트의 HTTP 계층** — `admin/server.js` 가 `module.exports` 없이 즉시 `listen`
하므로 app 을 꺼낼 수 있게 하는 소폭 리팩터가 선행이다. 기존 27라우트까지 덮는 것은
이번 범위 밖이고, **새로 만드는 것만** 붙인다

### 5.3 시험 대역 원칙

CLAUDE.md 의 규칙을 따른다 — **가짜가 실물보다 관대하면 시험이 거짓말을 한다.**
이 저장소는 그걸로 두 번 당했다.

- **pm2 가짜는 "무엇을 불렀나"를 기록해야 한다.** 성공만 돌려주면 ⑧이 아무것도 안 지킨다
- **부팅 기록 시험은 실제 파일을 쓴다**(임시 디렉터리). 메모리 목으로는 마스터 truncate ↔
  워커 append 경합을 못 본다
- **로그 파서는 실제 형식의 줄로** 시험한다

`npm test` 는 `node --test test/*.test.js` 라 `test/admin-*.test.js` 가 **이미 관문에 걸린다.**
없는 것은 CI 와 프런트 시험이다.

## 6. 작업 순서

배포 반영을 **두 번**으로 나눈다. 코어는 무해하니 먼저 올려 두고, 콘솔은 그 위에서 만든다.

| | 단계 | 파일 | 시험 |
|---|---|---|---|
| 1 | conf 키 내리기 | `conf_schema.js` · `mobius.js` · `app.js`(spId 이전) | 기존 19 + ①②③ |
| 2 | 부팅 기록 (상한 포함) | `mobius.js` · `mobius/boot_record.js`(신설) | ④⑦ |
| 3 | `windowsHide` 한 줄 | `app.js` | ⑤ |
| 4 | **포트 충돌 처리** | `app.js` · `mobius.js` | ⑥ |
| — | **배포 1차** — 코어 반영 + Mobius 재기동 | | 동작 불변 확인 |
| 5 | **실행 모듈 + CLI + npm 스크립트** | `tools/mobius-ctl.js`(신설) · `package.json` · `run_*.bat` | ⑧⑩ |
| 6 | 콘솔을 그 모듈 위로 | `admin/server.js` · `process_ctl.js` **삭제** | ⑨ |
| 7 | 3상태 판정 | `admin/conf_store.js` | ⑪ |
| 8 | 로그 읽기 | `admin/logs.js`(신설) | ⑫⑬ |
| 9 | 라우트 + app export | `admin/server.js` | ⑭ |
| 10 | 설정 탭 개선 | `ConfView.vue` | — |
| 11 | 실행 탭 신설 | `OpsView.vue`(신설) · `ServerControl.vue` 흡수 | — |
| 12 | 저장 → 재기동 연결 | 두 화면 | — |
| — | **배포 2차** — `adminPassword` 추가 + 콘솔 pm2 등록 | | |

**코어를 먼저 하는 이유**는 콘솔이 코어가 준 것(스키마·부팅 기록)에 의존하고 반대는 아니기
때문이다. 그리고 1~4가 배포에 무해하므로 먼저 올려 두면 콘솔 작업 중에도 배포가 안전하다.
배포에 `mobius-boot.jsonl` 이 생겨야 콘솔의 3상태가 "모름"을 벗어난다.

**4단계(포트 충돌)는 콘솔과 무관한 코어 결함 수정이다.** 지금은 운영 중에 중복 실행이 나도
아무도 모른다. 콘솔보다 먼저 고치는 것이 맞다.

**5단계가 실행 모듈이고, 6단계에서 콘솔을 그 위로 옮기며 `process_ctl.js` 를 한 커밋에
교체한다.** 반쪽만 바꾼 상태를 만들지 않는다. 딸린 시험 10건은 ⑧⑨⑩으로 대체한다.
5단계가 끝나면 **터미널 경로가 먼저 완성되므로**, 콘솔 작업 중에도 `npm start`·`npm run status`
로 Mobius 를 다룰 수 있다.

### 6.1 각 단계의 "끝났다" 기준

- **1~4** — `npm test` 전건 통과 + 빈 conf 로 띄워 전역이 지금과 같음 + 포트를 잡아 두고
  띄웠을 때 **좀비가 아니라 깨끗한 실패**가 되는 것을 실제로 확인
- **배포 1차** — 재기동 후 `pm2 jlist` 의 `restart_time` 이 안 늘고, `mobius-boot.jsonl` 이
  생기고, 응답이 전과 같음(`tools/response-golden/headers.js`)
- **5** — `npm start`·`npm run status`·`npm run mobius:restart` 가 터미널에서 동작.
  이미 돌고 있을 때 `npm start` 가 띄우지 않고 그 사실을 말함
- **6~9** — `npm test` 전건 통과. 특히 ⑧이 "다른 이름으로는 아무 호출도 안 간다"를,
  ⑨가 "콘솔에 pm2 직접 호출이 없다"를 실제로 증명
- **10~12** — 콘솔을 띄워 설정 저장 → 재기동 → 3상태가 "적용됨"으로 바뀌는 것까지 한 번에 걸어 봄
- **배포 2차** — SSH 터널로 접속해 같은 흐름을 배포에서 한 번

## 7. 배포 반영

### 7.1 원칙 — "동작이 안 바뀌는 변경"만 먼저

새 conf 키의 기본값을 지금 하드코딩 값과 같게 두면 배포 `conf.json`(5키)에 아무것도 안 넣어도
동작이 그대로다. `app.js` 의 `windowsHide` 한 줄도 Linux 에서는 무시된다.

### 7.2 순서

1. **pm2 버전을 6.0.14 로 핀한다** (`package.json`, 캐럿 없이)
2. **코어를 먼저 배포하고 Mobius 를 재기동한다.** 워커 24개 재기동이라 순단이 있다.
   콘솔보다 먼저 해야 하는 이유는 콘솔의 "지금 도는 값" 판정이 `mobius-boot.jsonl` 에
   의존하는데 그 파일은 **새 코어로 재기동해야 생기기** 때문이다
3. **`conf.json` 에 `adminPassword` 를 넣는다.** 지금은 없어서 배포에서 콘솔이 안 뜬다.
   **이 파일은 재현이 안 되므로 손대기 전에 백업한다**
4. **콘솔을 pm2 에 등록한다** — `pm2 start admin/server.js --name Mobius-Admin`.
   Mobius 와 같은 데몬에 붙되 별개 앱이다
5. **접속은 SSH 터널로** — `ssh -L 7580:127.0.0.1:7580 keti-server`.
   `adminHost` 기본값이 루프백이니 그대로 둔다. **인터넷에 열지 않는다** — 콘솔 비밀번호는
   사실상 superUser 키다

### 7.3 조심할 것

**배포 데몬에 앱이 17개고 16개가 같은 사용자 것이다.** §4.2 의 "이름 하나만 만진다"는 로컬에서는
형식적이지만 배포에서는 실제 안전장치다.

**다른 세션과 겹친다.** 배포 HEAD 가 오늘 `47e3a7e` 로 움직였고 재시작이 13회다.
`mobius.js` 와 `app.js` 는 지금 다른 사람도 만지고 있을 수 있으므로 **반영 전에 조율한다.**

### 7.4 pm2 7 업그레이드는 별도 작업으로

Node 22 라 요건은 만족하고 우리가 쓰는 API 표면에 깨지는 변화도 없다. 다만 7.0 의 변경 중
하나가 **TreeKill 재작성**이라 워커 24개의 종료 동작이 바뀐다. 배포가 지금 안정화 중이므로
겹치면 원인 분리가 어렵다.

**콘솔이 생긴 뒤 화면으로 지켜보며 올리는 편이 낫다.** 그때 확인할 것: `dump.pm2` 백업 /
`pm2-logrotate` 재설치 필요 여부 / `pm2 stop Mobius` 후 워커 24개가 다 정리되는지.

## 8. 실측 근거

전부 2026-09-04 에 직접 실행해 확인한 것이다.

### 8.1 창은 `cluster.fork()` 가 만든다

UI 에서 Mobius 를 띄우자 콘솔 창이 워커 수만큼 떴다(이 장비 16코어 → 16개).
Windows 는 콘솔이 없는 부모가 자식을 띄우면 자식에게 새 콘솔을 할당한다.
워커 2개짜리 흉내 스크립트로 변형을 갈라 측정했다(보이는 최상위 창을 열거해 소유 프로세스 확인).

| 변형 | 새로 뜬 창 |
|---|---|
| 아무 것도 안 함 (지금 코드) | **2개** |
| `spawn` 에만 `windowsHide` | **2개** — 무효 |
| `cluster` 에만 `windowsHide` | **0개** |
| 둘 다 | **0개** |
| pm2 + `HIDE_WORKERS=0` | **5개** |
| pm2 + `HIDE_WORKERS=1` | **0개** |

`spawn` 쪽 옵션은 효과가 없고 **`cluster` 쪽 한 줄이 전부**다. pm2 든 detached spawn 이든
같으므로 **이것은 실행 방식 선택과 무관한 문제**다.

### 8.2 `pm2 start <이름>` 은 이름을 경로로 먼저 해석한다

등록되지 않은 이름으로 불렀더니 **실패하지 않고** 존재하지 않는 경로를 스크립트로 잡은 채 떴다.

```
$ pm2 start Mobius
[PM2] Starting C:\...\Mobius\Mobius in fork_mode (1 instance)
[PM2] Done.          ← 그런 파일은 없다
```

지금 `process_ctl._pm2(['start', name])` 가 이 모호함 위에 서 있다.

### 8.3 `process_ctl` 의 소유권 판정은 터미널 기동을 못 다룬다

`ours` 의 근거가 **콘솔이 직접 적은 `.mobius-console.pid`** 하나뿐이라, 터미널로 띄운 Mobius 는
UI 에서 정지·재기동이 영원히 거부된다(`process_ctl.js:171`). 기조와 정면으로 부딪히는데,
**pm2 로 가면 통째로 사라진다** — 누가 띄웠든 pm2 가 주인이다.

### 8.4 배포 서버 현황

```
OS/CPU     Ubuntu · 커널 6.8 · 24 코어
node       v22.22.2
pm2        6.0.14
저장소     /home/keti/Mobius · lite · 47e3a7e
conf.json  5키 — csebaseport, dbpass, db, dbConnectionLimit, dbQueueLimit
Mobius     pm2 name=Mobius · fork_mode · online · 재시작 13회
pm2 앱     17개 (Mobius 외 16개는 같은 사용자의 다른 서비스)
액세스로그 하루 53~71MB
pm2 로그   Mobius-error 하루 3~5MB · pm2-logrotate 설치됨 (10M/10개/매일 0시)
```

### 8.5 pm2 프로그래매틱 API 가 주는 필드

`pid` · `status` · `restart_time` · `unstable_restarts` · `pm_uptime` · `exec_mode` ·
`instances` · `pm_exec_path` · `pm_cwd` · `pm_out_log_path` · `pm_err_log_path` ·
`memory` · `cpu`

로그 경로까지 API 가 직접 주므로 경로를 추측하거나 리다이렉트를 만들 필요가 없다.

### 8.6 콘솔은 코드 수정 없이 뜬다

막는 것은 빌드가 아니라 `conf.json` 이다. `adminPassword` 가 없으면 프로세스가 아예
`exit(1)` 한다(`admin/server.js` 의 기동 관문). 빌드 부재는 2차 장벽이고, 서버는 뜨고 `/` 만 503 을 준다.

### 8.7 중복 실행은 좀비가 되고, pm2 는 정상으로 본다

`app.js` 의 기동 구조(cluster 마스터 + 워커, `listen` 에 `.on('error')` 없음, 워커
`uncaughtException` 시 워커만 종료)를 그대로 본뜬 껍데기로 측정했다. Mobius 도 DB 도
건드리지 않았다.

**포트를 먼저 잡아 두고 두 번째 인스턴스를 띄운 결과:**

```
[B][worker] uncaught: EADDRINUSE — 워커만 종료한다
[B][master] 워커 죽음 (누적 1, 0초)
[B][master] 워커 죽음 (누적 10, 4초)
...            12초에 20회 이상. 마스터는 계속 살아 있다
```

**같은 상황을 pm2 로 띄웠을 때 pm2 가 보고하는 것:**

```
5초 후   status online · restarts 0 · pid 고정
12초 후  status online · restarts 0 · pid 고정
```

마스터가 안 죽으니 pm2 는 이상을 못 본다. **cluster 가 아닌 단일 프로세스였다면** pm2 가
재시작하다 `errored` 로 포기했을 것이다(실측 `restarts 30` → `errored`). Mobius 는 마스터가
살아 있어서 그 안전장치가 작동하지 않는다.

**그리고 `pm2 start <이름>` 은 이미 `online` 인 앱에 불러도 거부하지 않는다:**

```
[PM2] Applying action restartProcessId on app [mobiusfake](ids: [ 0 ])
```

거부가 아니라 **재시작**이다. 콘솔의 [기동] 버튼이 돌고 있는 Mobius 를 말없이 재기동시킬 수
있다는 뜻이라, 모듈이 상태를 먼저 봐야 한다(§4.8 다).

## 9. 정하지 않은 것

- **`ecosystem.config.js` 를 둘 것인가** — `tools/mobius-ctl.js` 가 이름·경로·모드를 이미
  갖고 있고 터미널 경로도 그 모듈을 지나므로 **필수가 아니게 됐다.** 다만 `pm2 resurrect`
  로 서버 재부팅 뒤 복구할 때는 pm2 가 자기 `dump.pm2` 를 쓰므로 그것으로 충분한지
  구현하며 확인한다
- **콘솔을 배포에서 상시 띄울 것인가** — `pm2 save` 로 부팅 시 복구 목록에 넣을지.
  콘솔이 운영자의 진입점이라면 상시가 맞다는 쪽으로 기운다
- **`npm run status` 의 출력 형식** — 사람이 읽는 표인지 `--json` 도 줄지
- **`cluster.setupPrimary` 를 `app.js` 어디에 둘 것인가** — fork 루프 앞이라는 것만 정했다
- **배포 소스의 `usecsebase`·`usecseid`·`usespid` 실제 값**이 이 문서가 적은 기본값과 같은지.
  배포 HEAD 가 달라 다를 수 있으므로 **1단계 착수 전에 확인한다**
