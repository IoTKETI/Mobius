- **작업 브랜치**: `lite` (전부 병합·배포 완료)
- **대상 구간**: `994c57e` … `044f29a` 중 본 세션 몫. 같은 구간에 DB 레이어 세션의 커밋이 섞여 있으므로 아래 표의 SHA 로 가른다
- **근거 문서**: [요청 처리 흐름 구조 분석](../specs/2026-08-26-request-flow-perf-analysis.md) — 이 작업이 그 문서의 D13·D14 계열을 처리했다

## 1. 무엇을 했나

### 1.1 json 전용 전환

이 CSE 는 이제 **json 만 다룬다.**

| 커밋 | 내용 |
|---|---|
| `05d76a5` | xml/cbor 파서와 npm 의존성 넷 제거 |
| `7e1e14f` | `responder.js` 의 XML 직렬화 514줄 제거 (그 시점 1,275 → 775줄) |
| `2d6d636` | WS·MQTT 응답의 xml/cbor 직렬화 제거 |
| `52f46b1` | 시맨틱 브로커 호출 제거 (`smd.js` 222 → 58줄) |
| `6babc57` | ASN/MN-CSE 모드 제거 (`asn.js`·`mn.js`) |
| `044f29a` | 값이 언제나 `'json'` 인 `bodytype` 인자 제거 |

**지우기 전에 관문을 먼저 달고 운영에서 관찰했다.** 요청이 xml/cbor 이면
`[json_only]` 로그를 남기는 게이트를 배포해 두고, 실제 트래픽에서 며칠을
지켜봤다 — 하루 3만 5천 요청에서 **실제 히트 0건**이었다. 그 0이 삭제의 근거다.

관문은 세 곳에 남아 있다. 지금은 `400-64` 로 거절한다.

```
HTTP    Content-Type
WS      서브프로토콜
MQTT    토픽 끝
```

**되살리려면 그때 새로 만든다.** 절반만 남은 코드를 두는 것보다 낫다는 판단으로
지웠다. `semanticDescriptor`(24) **리소스 자체는 그대로다** — 없앤 것은 외부 브로커
호출뿐이고, `?smf=` 는 일반 discovery 로 떨어진다.

### 1.2 본문 수집 — `mobius/body.js`

요청·응답 본문을 모으는 자리를 **한 곳으로 모았다.**

| 커밋 | 내용 |
|---|---|
| `994c57e` | 요청 본문 (D13). 한글 손상과 죽어 있던 크기 상한 |
| `a3912db` | 응답 본문 **여섯 자리**. 팬아웃이 한글을 조용히 깨뜨리고 있었다 |
| `112949b` | 상한 초과 사유가 도달 불가능했던 것 |
| `09d2510` | 끊긴 응답을 **진짜 소켓**으로 잠그는 시험 |

무엇이 깨져 있었나:

- **`+= chunk` 가 멀티바이트를 깬다.** 청크 경계가 UTF-8 시퀀스 가운데를 지나면
  그 글자가 U+FFFD 가 된다. `setEncoding('utf8')` 은 StringDecoder 를 붙여
  이것을 막아 주는데, **응답 쪽 여섯 자리에 그게 없었다.** 실제로 재현했다
- **크기 상한이 걸리지 않았다.** `body-parser` 의 `type` 옵션에 세미콜론으로 이은
  단일 문자열을 줬는데 `type-is` 는 그것을 쪼개지 않아 **어떤 content-type 과도
  매칭되지 않았다.** 6MB 본문이 201 로 통과하는 것을 확인했다

`collect()` 는 청크를 모아 `Buffer.concat` 으로 **한 번에** 디코드한다.
`request.body` 는 **문자열**로 둔다 — `!== ""` 검사와 `req.write` 소비자를
건드리지 않기 위해서다.

상한 초과는 두 갈래다. **선언된 `Content-Length` 가 넘으면 즉시 413**, 아니면
**다 받고 나서 413** 이다. 일찍 끊으면 클라이언트가 413 을 읽기 전에
`ECONNRESET` 을 받는다 — 실측으로 확인한 뒤 이렇게 정했다.

상한은 `conf.maxBodyBytes`(runtime, 기본 10MB)로 관리 화면에서 바꾼다. 배포
실측 최대 본문이 약 4MB(전부 base64 JPEG)라 **2.5배 여유**를 뒀다. 그보다
낮추면 정상 쓰기가 막힌다.

### 1.3 로그 위생

| 커밋 | 내용 |
|---|---|
| `951171c` | 요청·응답 본문을 통째로 찍던 **일곱 자리** |
| `997c8ee` | **수퍼유저 origin 이 운영 로그에 평문으로** 적히던 것 |

두 번째가 더 심각하다. `superUser` 값을 `X-M2M-Origin` 에 넣으면 **모든 ACP 검사를
건너뛴다** — 사실상 마스터 키다. 그것이 로그 파일에 남고 있었다.
`mobius/log_safe.js` 의 `origin()` 을 거치면 `<superuser>` 로 치환된다.

**이 결함은 내가 만들었다.** 본문 로그를 지우면서 진단을 돕겠다고 `origin=` 을
새로 넣었고, 그 값이 수퍼유저일 수 있다는 것을 놓쳤다. 운영 로그에서
`origin=Sponde` 를 확인하고 고쳤다.

## 3. 이 작업에서 배운 것

세 가지는 방법의 문제였고, 여기 적어 두면 다음에 시간을 아낀다.

**관문 → 관찰 → 삭제.** 코드를 읽어 "안 쓰는 것 같다" 로 지우지 않았다. 게이트를
배포해 운영 트래픽에서 0을 확인하고 지웠다. xml/cbor 이 그렇게 나갔다.

**테스트 대역이 실물보다 관대하면 시험이 거짓말을 한다.** 두 번 당했다.
가짜 스트림의 `destroy()` 가 `'aborted'` 를 안 뿜어서 **깨진 코드 위에서 시험이
통과**했고(`112949b` 가 그 수정이다), 직접 emit 한 이벤트를 Node 가 정말 주는지
확인하지 않았다. 그래서 `09d2510` 에서 **진짜 소켓**으로 바꿨다.

**`res.destroy()` 는 `'aborted'` 를 동기로 뿜는다.** 그래서 `finish()` 를 **먼저**
불러야 한다. 순서가 반대면 "N 바이트를 넘었다" 는 사유가 영원히 도달하지
못하고 `aborted` 가 이긴다.

## 4. 남은 것 / 하지 말 것

### 이어서 할 수 있는 것

- **`request.usebodytype` 이 아직 남아 있다.** 없앤 것은 함수 **인자**였고
  (`044f29a`), 요청 객체의 이 필드는 세 자리에서 `'json'` 으로 대입된 채 남아
  있다 — `app.js:1645`·`app.js:1648`·`mobius/responder.js:129`. 값이 하나뿐이라
  읽는 쪽이 분기하지는 않지만, **형식이 아직 선택 가능한 것처럼 보이게 한다.**
  걷어내려면 읽는 자리를 먼저 세어야 한다
- **`cty` discovery 30초 절벽** — 다른 세션이 맡았다. `265238a` 에서 지원하지
  않는다고 400 으로 끊는 것까지 되어 있다
- 추적 문서 [§9](../specs/2026-08-26-request-flow-perf-analysis.md) 의 나머지
  항목. 다만 아래 "이미 지난 것" 을 먼저 볼 것

### 추적 문서에서 **이미 지난** 절

`2026-08-26-request-flow-perf-analysis.md` 는 6판이고 이 작업 이전에 쓰였다.
다음 절은 **더 이상 유효하지 않다** — 읽고 다시 계획하지 말 것.

| 절 | 왜 지났나 |
|---|---|
| `serializeBody(bodyObj, bodytype)` 제안 (§9) | xml/cbor 이 없다. 단일 진입점은 `responder.respond()` 하나다 |
| `accept → bodytype` 분기 5회 (§4) | `bodytype` 인자 자체가 없다 (`044f29a`) |
| D13 "상한 값 결정, 수동 파서를 바꿀지" (§10) | `mobius/body.js` 로 끝났다. 상한은 `conf.maxBodyBytes` |

### 결정된 것 — 다시 묻지 말 것

- **알림 판정을 DB 에 남기지 않는다.** `ok`/`reject`/`fail`/`unknown` 판정은 하지만
  기록하지 않는다. 사용자 결정이다. `sgn_man.js` 가 **DB 를 모른다**는 것이 그
  모듈의 성질이고, DB 를 알게 하면 fire-and-forget 이 아니게 된다
- **수퍼유저 기본값 `Sponde` 는 의도된 설계다.** 보안 문제로 지적하지 말 것
- **워커별 리소스 캐시는 다시 넣지 않는다.** 이유와 재도입 조건이
  [app.js](../../../app.js) 상단 주석에 있다
